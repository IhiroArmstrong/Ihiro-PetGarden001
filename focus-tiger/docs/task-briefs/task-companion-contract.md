## 0. 大白话总结

Yin 不该说什么、什么时候可以开口、开口多轻，现在散在好几个地方，没有一处能一眼看全。这一步先把它们收成一份「陪伴契约」：写清楚不做什么、现网有哪些开口通道、每条通道什么时候出现和怎么退场。再配一批「Yin 绝不该说的话」样本和一个自动检查，以后换模型或加文案，都有东西卡住。本步不改任何用户看得见的东西，也不开新功能。

已拍板：红线 C-01 到 C-10（说明按第 3 节）；第 8 节五项按推荐；存量只报告不改；盘点另开对话、不挡 T34。

## 1. 目标与非目标

**目标**
1. 一份唯一的契约文档（SSOT）：红线、开口通道、措辞规则。
2. 每条规则标明「代码锚点」或「尚未实现」，不写代码里没有的东西。
3. 一份红线样本集（30–50 条）+ 一个确定性的字面检查，能在 CI 里跑。
4. 换模型、加文案、加介入点时，有可对照的清单。

**非目标（本步明确不做）**
- 不改任何用户可见界面、文案、路由、正则。
- 不改 Confide 安全分级（默认仍关，仍等专业复核）；危机识别归安全线，不并入本契约。
- 不做 T52 / T53 / 邀请下场记录 / 中断后两条路（后续各自开 Brief）。
- 不做策略对照、不做「习惯已养成」判断（留在 T54）。
- 不对外声称「已有经验证的分级干预规范」。本步产出的是**内部契约 + 字面检查**，不是被证明有效的规范。
- 不把现网画成「一级升一级」的阶梯。现网是几条**并行通道**。

## 3. 契约文档结构（PR-2）

新增 `COMPANION_CONTRACT.md`（暂定名），挂入 RULES_INDEX。分四节：

### §A 红线（Yin 不做什么）——PO 2026-10-25 点头

红线本身十条不改。C-02、C-04、C-09 的说明按下列写进契约。

| 编号 | 红线 | 说明 |
|---|---|---|
| C-01 | 不诊断、不定性 | 不说用户「焦虑 / 抑郁 / 注意力有问题」，不给情绪贴病理标签 |
| C-02 | 不打分、不排名、不报指数 | 不出现分数、心流指数、百分比**评价人**。练习事实（同坐天数环、莲花计入分钟）不算给人打分，检查器不得误伤 |
| C-03 | 不替用户下结论 | 不说「你今天状态不好」；只描述可观察的事，且用观察语气 |
| C-04 | 不催促、不制造愧疚 | **允许问候，禁止缺席、天数、愧疚。** 不拿连续天数、缺席、「你错过了」施压；归来问候不带账 |
| C-05 | 不承诺疗效 | 不说「这会治愈你 / 让你好起来」 |
| C-06 | 不冒充专业 | 不以治疗师 / 医生 / 导师身份说话 |
| C-07 | 不制造依赖或排他 | 不说「只有我懂你」；不留人，不挽留 |
| C-08 | 不替用户做决定 | 邀请必须可拒绝，拒绝后不追问、不重复 |
| C-09 | 不外泄内部状态估计 | **硬规则。** 系统内部对用户状态的估计（含现网 `SETTLED` / `DRIFTING` / `STRUGGLING` 一类名字）不以任何形式显示给用户；以后也不许接到界面上 |
| C-10 | 危机话题不由陪伴话术承接 | 交给安全线；契约只写「交接点」，不重写安全逻辑 |

### §B 开口通道（Yin 什么时候开口，开口多轻）

现网是**并行通道**，不是 L0→L3 一级升一级。禁止写「只升不跳」。空格写「待盘点」，不许编。

| 通道 | 触发条件 | 冷却 | 用户不理时 | 代码锚点 |
|---|---|---|---|---|
| 结束低语 | 待盘点 | 待盘点 | 待盘点 | 待盘点 |
| 专注中邀请 | 专注中等（待核实） | 一小时一次；十分钟内不再问（待核实） | 约 10 秒消失，不追问（待核实） | `InterventionOrchestrator`（待核实行号） |
| 离开后再聚焦提示 | 待盘点 | 待盘点 | 待盘点 | 待盘点 |
| 到达后的安静句 | 待盘点 | 待盘点 | 待盘点 | 待盘点 |

通道硬规则（草案）：

- 被用户点头才进入短练习；邀请必须可拒绝。
- 任何一条被忽略都只退、不加码。
- **同一时刻只有一个开口**：保留为**目标**，标明**尚未实现**。现网多通道可并行；对接现有叠层 / 精灵通道仲裁，本步不另建、不改运行时。

### §C 措辞规则

- 观察式，不诊断式；描述发生了什么，不解释用户是什么人。
- 禁词表（字面层）：按语言维护，**en 与 ja 为正式，zh 为草稿**（与「对外只 claim en+ja」一致；英文为第一优先）。
- **现网缺口（PR-3 补）**：`AWAKEN_FORBIDDEN_COPY` 只抓焦虑、分心诊断、心流指数、分数。C-01 到 C-10 的其余字面不在现网正则里。
- 允许的近邻说法要列出（如描述性的「你离开了两次」、练习事实「近日同坐」），防止检查器误拦。

## 4. 红线样本集 + 字面检查（PR-3、PR-4）

**样本集（PR-4）**：约 40 条，英文为主、日文次之。每条：`id / 语言 / 场景 / 类别 / 绝不该说的话 / 方向（该怎么回，描述方向而非唯一句）`。

| 类别 | 条数（目标） |
|---|---|
| 诊断/定性（C-01） | 6 |
| 打分/指数（C-02） | 4 |
| 催促/愧疚（C-04） | 6 |
| 疗效承诺/冒充专业（C-05/06） | 5 |
| 依赖/排他（C-07） | 5 |
| 替人下结论/越权（C-03/08） | 5 |
| 内部状态外泄（C-09） | 3 |
| **边界邻近的正常说法（必须放行）** | 6 |

最后一类很重要：用来测检查器**不过度拦截**（含练习事实、无账的归来问候）。合入后须含近日同坐环悬停（一天一个亮点）与一条分钟或天数练习事实，专门测 C-02 不误伤。

**比率口径（PO 2026-10-25）**：合格线维持 1.0 / 1.0。34/34 是回归结果，不是覆盖率，也不是「已验证」；这个数字对外不能引用。日文样本目前不算覆盖，真正日文样本另做并走人审。「已知漏网」一栏另开小任务，不挡 PR-4。

**字面检查（PR-3）**：确定性脚本，不调模型。
1. 扫描现网用户可见字符串（文案池、低语、邀请）对照禁词表，输出命中报告。
2. 对样本集跑检查器：坏样本应被命中，边界邻近样本应放行；两个比率各自单独报告。
3. 存量命中走**豁免表，只减不增**（沿用 #1188 做法）；新增命中直接让检查失败。
4. 把现网 `AWAKEN_FORBIDDEN_COPY` 的窄范围扩成契约禁词表，或并列报告「仅邀请通道已覆盖 / 其余通道未覆盖」。

**诚实边界（写进契约和脚本输出）**：字面检查只能抓字面。换种说法的违规它抓不住。所以通过检查 ≠ 模型不会越界；也不得据此对外说「已验证」。

**样本卫生**：入库样本仅用于回归，不是盲测。将来若要对模型输出做真验证，需另建封存集，且生成它的会话不得见过入库样本。本步不做封存集。

## 6. 验收

- 契约每条规则都有「代码锚点」或明写「尚未实现」。
- 开口表是通道表，不是升级阶梯；文中无「只升不跳」。
- `npm run check:companion-contract`（暂定名）本地与 CI 都能跑，退出码可靠。
- 坏样本命中率、放行样本放行率分别报告，不合成一个数。
- 存量违规清单存在，豁免表只减不增有测试守着。
- 全程零用户可见变更；`git diff` 中无 src 运行时文件。
- 汇报按既有格式：开头大白话总结，随后「计划→现状→还差→下一步」对照表。
