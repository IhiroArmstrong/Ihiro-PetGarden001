**结论**：前四条里，**光加载** 的 p50 已超过结束低语与到达句上限；p95 超过到达句；邀请条在加载之上还要加提示词与生成，**大概率**仍超。本探针 **不是** 生成总耗时。

### 2.2 读数局限（禁止当「真实冷启动已经这么快」）

1. **只含加载**，不含 tokenize / 生成 / 禁词校验。冷路径总墙钟 = 加载 + 生成，会更长。  
2. **偏乐观下限**：连续 load 十次，GGUF 多半已在系统页缓存。睡眠唤醒、隔很久再开口会更慢。  
3. **进程模型不同**：实验室 Node 的 RSS **只作数量级**，不是阶段 2 内存基线 B 的证据。  
4. **不能代替** 四通道 Electron 手测开口瞬间的 `modelWarm`。本评估用 **代码路径** 代替 40 次手测（见 §3），因 focusing 卸载是硬接线，不是概率事件。

| 继续热测 | **不采用** | 热 = 专注期间常驻约 2.5GB RSS 增量，与 `setFocusing(true)` → **立即 unload** 冲突；对 16GB 以下不友好。 |

## 3. 四通道开口时模型冷热（读代码，不是 40 次手测）

`modelWarm` 口径仍是阶段 0：`phase === 'ready'` **且** `focusing !== true`（[`constrainedGenModelWarm.js`](../../src/core/constrainedGenModelWarm.js)）。Focusing 时 `l1Runtime.setFocusing(true)` **立即 `unload()`**，无 60s 宽限。关倾诉 / 壳隐藏才走 `COMPANION_UNLOAD_GRACE_MS = 60000`。

接线：[`main.js`](../../src/main.js) `stateManager.onChange` → `companion.setFocusing(stateManager.state === STATES.FOCUSING)`；[`l1Runtime.js`](../../desktop/companion/l1Runtime.js) `setFocusing` 在 `focusing===true` 时 `await this.unload()`；`generate()` 在 `status.focusing` 时直接 `reason: 'focusing'`。

| 通道 | 何时开口（代码） | 开口瞬间 focusing？ | 模型冷热 | 当拍生成 |
|---|---|---|---|---|
| **专注中邀请** | `tryShowAwakenInvite` **要求** `state === FOCUSING` | **是** | **冷（近 100%）** | 不可行。池须在 Sit **之前**备好，开口只取用。 |
| **离开后再聚焦** | `MindfulReminderController.handleAttentionReturn` 仅 `sessionActive`；现网在计时专注中离开再回 | **通常是**（仍在 FOCUSING） | **冷（高）** | 同上。 |
| **结束低语** | 会话结束后 `maybeOfferMomentWhisper`（Reflection 打开时等）；`onChange` 已把 focusing 置 false，但会话中已被 unload | **否**（刚离开 FOCUSING） | **冷（高）** | 刚结束时模型通常仍未 reload；当拍会再付一次加载。池应在专注前备好并在结束时取用。 |
| **到达后安静句** | Arrival 开始后 `maybeOfferMomentWhisper('arrive', { delayMs: 500 })`，**专注前** | **否** | **中**：冷启动 App / 已过 60s 闲置 unload → 冷；倾诉刚就绪且 60s 内 → 可能热 | 唯一可能热的通道。即便热，加载探针 p50 仍贴 3000ms 上限。池化仍更稳。 |

**四通道冷启动大概几成（代码结论，不是手测比例）**：邀请 / 再聚焦 / 结束低语在「按现网卸载策略」下应视为 **几乎全冷**；到达句视前序是否刚用过倾诉，**不能**当成四通道整体已热。

## 4. 预生成池方案（评估口径 · 未实现）

### 4.1 句子存哪里

**只放内存，不落盘。**

| 允许 | 禁止 |
|---|---|
| 进程内 Map / 数组（建议：渲染进程持有已校验短句；companion 子进程生成完即卸载） | `localStorage` / IndexedDB / 文件 / 实验室 JSON 夹带原文 |
| 只存通道 id、locale、已过禁词的短句、入池时刻 | 提示词、用户原话、未校验草稿、倾诉 `turns` |

理由：落盘会让「本机不记原文」变模糊。重启丢失 **可接受**（池空则回退检索）。

### 4.2 什么时候生成

同时满足才允许填池（实现时再锁函数名）：

1. 桌面 companion **允许**（非低配、Electron 宽屏既有闸）。  
2. **非** `FOCUSING`（不得与「专注时卸载」对着干）。  
3. **空闲**：无倾诉进行中的 generate、无冷启动第一幕抢同一把锁。  
4. 不与 `ensureReady` 给倾诉的首次加载死抢；若模型已为倾诉 resident，可顺带填池后仍按现网闲置 60s 规则卸载。  
5. **生成完立即 unload**（除非倾诉仍需要 resident）。专注期间池已在内存，**不**为此保持 GGUF。

推荐窗口：**到达之后、点 Sit 之前** 的空闲；或 Idle 且用户未开口的数秒。禁止在开口回调里现场 `ensureReady`。

### 4.3 池子大小与过期

| 项 | 建议（实现 Brief 可改数字，须 PO 点头） |
|---|---|
| 每通道条数 | **3** 条已校验变体（四通道合计 ≤12） |
| 取用 | 开口取 1 条并 **从池删除**；同会话不复用同一变体 |
| 过期 | 入池后 **30 分钟**，或下次 Sit 开始前未取用则作废重建 |
| 重启 | 池空；不恢复 |
| 低配 | **永不填池**；恒为检索臂 |

### 4.4 校验在哪一步

```
空闲 generate（短、通道专用约束）
  → matchForbiddenPatterns（与 CI 同一张表）非空 → 丢弃，不入池
  → 超长 / 空 / 非目标 locale 串扰 → 丢弃
  → 入池
开口
  → 池有可用句 → 展示（不再 generate、不再二次模型校验）
  → 池空 → 检索/固定句，记 pool-empty
```

红队评测对象变成 **「池里的句子」**（加「填池失败 / 池空回退」），而不是开口当拍延迟。

### 4.5 阶段 2 判据改写（路径 A 时）

父 Brief §5.4.2 的开口延迟表 **对取用路径基本不适用**（取用是内存读，应远低于 2500ms）。须改看：

| 指标 | 建议线（实现 Brief 锁定前可改） | 含义 |
|---|---|---|
| **池空率**（按通道） | 开口时无可用已校验句、因而回退检索的比例 | 主成本/可用性线 |
| 填池成功率 | 一次空闲填池产出 ≥1 条可入池句 | 生成质量在空闲侧 |
| 填池是否碰到 focusing | **0** | 不得在专注中加载 |
| 开口墙钟 | 取用 p95 应远小于原 §5.4.2；**超时不得**再记成模型 timeout | 证明没在开口时 generate |
| 禁词漏放行 | 仍 **0**（入池前闸） | 安全线不改 |

**无意义停臂**：某通道池空率持续过高（实现 Brief 写死数字，建议沿用「>65% 回退」精神）→ 该通道停池化，只留检索。禁止为凑样本在开口瞬间改回当拍生成。

内存：路径 A **不应** 在专注中把 GGUF 算进「生成边际」。基线 A（冷机整包权重）仍须披露；基线 B（resident 后再生成）适用于 **填池那一次**，不适用于开口。
