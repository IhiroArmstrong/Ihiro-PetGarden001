## 一句话

小圈的六位暗号照旧。另发一种一次有效的「请你坐在旁边」：发给一个人，用过即废，不能当商品转卖。邀请人只多看见「你请来的人来过」；被请的人看见的仍是现在小圈已有的轻痕迹。坐禅不靠这张码。

## 已拍板（勿再开放）

1. **两扇门，主次写死**
   - **小圈门锁**（场景 AN）：6 位暗号 + `?circleJoin=`。一圈共用，可继续转发进同一间，上限仍 8 人。本任务不改创建、加入、离开、复制暗号。
   - **请坐码**：另发、一次一人、成功进圈后作废。进的是邀请人**已经在的那一圈**，不另开房间，不另造全球灯火。
2. **谁能发**：邀请人必须已经在一圈里。还没有圈 → 诚实短句请先建圈或加入，**不**在发码时偷偷建圈。
3. **张数**：每人**同时最多 3 张未使用**。用掉、或自己作废，空位可再发。不设终身总量，也不做倒计时。面板可写静事实「还可以请 2 位」，禁止「所剩不多 / 快邀请」一类催促。
4. **作废时机**：只有**成功加入**才消耗。圈已满 8 人、暗号不匹配、云端失败 → 码仍可用，并见诚实失败句。邀请人可手动作废一张未使用的码，空位立刻回来。
5. **不能当商品**：码在云端绑邀请人的本机 `memberId`。谁先成功加入，谁坐进来；之后再使用同一码，见「已经用过」。产品不保证没人截图转发，保证的是**用一次就没了**。文案只写「给一个人。用过就作废。」
6. **邀请人看见什么**：只在**已有的我的小圈面板**里多一句。今日有「你请来的、且已成功加入的人」满足现有 was-here（场景 AQ）时，显示「你请来的人来过」。两人及以上仍是这一句，**不**列名单、**不**比分钟、**不**上 Idle。恰好一人且对方有昵称、本机未隐藏 → 可用该昵称替换「人」；否则保持「你请来的人」。
7. **被请的人看见什么**：与普通圈成员相同（坐着的点、今日来过、一句痕迹、可选昵称）。不多看日历、收件箱，不互传文件，不出现「你是被邀请的」特殊面板。
8. **坐禅**：无圈、无码、码失效，Sit / Arrival / Honesty 照旧。码不挡练习。
9. **码形**：8 位，与 6 位暗号不同长，字符集沿用暗号那套（避开易混字符）。深链 `?besideJoin=`，**不**复用 `?circleJoin=`。把请坐码贴进旧的加入框 → 「无匹配」类现有失败，不误进别的圈。
10. **身份**：仍是本机 `memberId`，不是账号。换设备 / 清缓存后，邀请人这边可能看不见自己发出的码（与现有小圈一样）。本任务不写跨设备 OTP。
11. **离开**：邀请人退圈 → 其未使用的请坐码作废。已经进来的人留在圈里，直到自己离开。
12. **关闸**：`?besideSeat=0` 藏起请坐控件且不发请坐请求。`?focusCircle=0` 仍整圈关闭（含请坐）。
13. **指标（无界面）**：云端只给被请且已加入的成员记 `joinedAt`，并在**现有**圈内心跳写到「在坐」时补一个日期戳 `sawSittingOn`（可多日）。不新开轮询，不做漏斗页、不做日环比。要看的是：被请的人是否坐完一次、过几天是否还回来。
14. **生产**：源码合入 ≠ 现网。请坐接口须另口令「部署」后 Worker 才有。未部署时发码 / 加入见失败句，不挡 Sit。
15. **不做**：亲人 vs 同事可见度、PDF / 图片 / 表格互传、eBay 式限量入场、拉新榜、聊天、精确在线名单、把 3 张改成终身 5 张。

## 冲突扫描

对照场景 AM（全球灯火）、AN（六位暗号）、AO（圈内在坐）、AP（痕迹）、AQ（今日来过）、AR（昵称）。

| 轴 | 结论 |
|---|---|
| **a. 强度** | 发码 / 复制 / 作废都在已经打开的小圈面板里，比 Sit 轻，不重于 Recover。 |
| **b. 语气** | 观察式短句。禁止催促发码、禁止人数排行、禁止「不够专注」。 |
| **c. 职责** | AN 仍是一圈共用的门锁。请坐码是发给一个人的一次性座位，进同一圈。AQ 的「来过」粒度不变，只允许多一句「你请来的人来过」，禁止变成在线名单。 |

PO 已于 2026-10-08 书面选定这一拆分。无未决冲突。

## 点击反馈

发一张 / 复制 / 作废 / 用请坐码加入：

- **0–1 秒内**：按钮 disabled，或面板内见挂起短句。
- **成功**：见结果句（已发出、已复制、已作废、已坐下）。复制句在人数刷新后仍留着，直到用户做下一个动作（与场景 AN 第 5 步同一条）。
- **失败**：见失败句，按钮恢复。圈满、已用过、未建圈，各一句，不静默。
- 不挂 `SILENT_BEHAVIORS`。设计上没有「点了没反应」。

## 后台网络三问

1. **时机**：发码、加入、作废 **仅用户点击**。`joinedAt` / `sawSittingOn` 搭在现有圈内心跳写路径上，**不**新开定时拉取。
2. **写盘**：仅成功响应后写入本机「未使用码」草稿；同内容跳过。失败不清掉已在圈内的 membership。
3. **卡顿**：不 await Sit。失败短句留在小圈面板。云端超过约 12 秒无响应 → 失败句 + 可再点（与 AN 建圈超时同档）。

## 验收（实现 PR 升格为场景 AU；本 PR 不改剧本）

1. 已入圈 → 小圈面板发一张请坐码 → 0–1 秒内见 8 位码；「还可以请」从 3 变为 2。
2. 另一配置用该码加入 → 圈人数 +1，码不能再用；邀请人面板在对方今日满足 was-here 后见「你请来的人来过」。
3. 第三个人再用同一码 → 「已经用过」，人数不增加。
4. 满 8 人时用一张未消耗的码加入 → 满员句，该码仍可在有人离开后使用。
5. 未入圈的人点发码 → 先建圈短句，不产生码。
6. 无圈用户 Sit 照旧；`?besideSeat=0` 不见请坐控件。
7. 六位暗号 Create / Join / Copy / Leave 与场景 AN 相同。

单测锁：配额 3、成功才消耗、满员不消耗、8 位与 6 位不混用、Sit 不读请坐码。E2E 只锁主干第 1–2 步；其余组合用单测。
