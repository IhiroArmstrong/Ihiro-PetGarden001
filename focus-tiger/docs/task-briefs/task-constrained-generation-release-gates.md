## 4.1 阶段 0 第一件事（阶段 1 硬闸 · 评测前锁定）

**禁止**在未完成本节交付物并取得 **PO 书面认可** 前启动阶段 1 红队或阶段 2 试点。避免花两周得到「全部 cold-start / 超时回退」而结论本可预见。

### 4.1.1 模型 warm / cold（与 §3 四通道强相关）

**现网假设（须实测，不得照抄）**：专注进行中 companion 可能 **unload GGUF 以省内存**（见 `ARCHITECTURE.md` / companion unload 与 `focusing` 状态）。因此 **结束低语、专注中邀请、离开后再聚焦** 等多发生在 **专注前后**，开口瞬间模型 **常为 cold**（冷加载常 **秒级～十几秒**），而 §5.4.2 延迟表按 **warm** 设计——若不做区分，会 **必然** 击穿 2500–5000ms、回退率 **>65%**，生成臂被自动关停，但 **学不到** 安全/偏好，只学到「冷启动不适合当拍生成」。

**阶段 0 交付物 A · warm/cold 实测表**（Electron 宽屏 · stage 0 锁定 quant · 各通道 **≥10** 次真实或等价复现路径）：

| 列 | 要求 |
|---|---|
| 通道 | §3 四行各报 |
| 触发时 `modelWarm` 判定口径 | 写清读口（例：companion `ready` / `getLlama` 已持有 / 无 unload 宽限中） |
| **cold 占比** | 该通道触发中 cold 的比例 |
| cold 时 **time-to-warm**（p50 / p95） | 只报 ms，不记原文 |
| 与 §5.4.2 关系 | cold 且 p95 time-to-warm **>** 该通道延迟上限 → 标注「当拍生成不可行（预见）」 |

**日志（实现 PR；规格本 Brief 先锁）**：

| 字段 | 要求 |
|---|---|
| `modelWarm` | `true` / `false`（与阶段 0 判定口径一致） |
| `fallbackReason` | 须含 **`cold-start`**（模型 cold 且未走当拍生成）与 **`timeout`**（warm 下超 §5.4.2）**分开**；禁止把冷启动记成 timeout |

**PO 书面认可时的分支（三选一，写进阶段 0 结论页）**：

| 分支 | 何时选 | 对阶段 1 / 2 的含义 |
|---|---|---|
| **继续 · warm 实验室** | 四通道 cold 占比低，或实验室可 **预 warm** 且与用户路径等价 | 阶段 1 红队 **仅统计 `modelWarm=true` 的延迟** 对 §5.4.2；cold 机会一律 `cold-start` 回退，**单独报告**，不混进 warm p95 |
| **(B) 缩 scope** | 多数通道 cold 且当拍不可行 | Listed 通道 **暂不做当拍生成**（仅检索）；阶段 1/2 **不跑**被删通道的生成臂 |
| **(A) 预生成池** | 多数 cold 但仍要变体 | **须另开 B 类 Brief**（空闲预生成+校验+开口取用）；**本 Brief 不展开**。**PO 2026-11-01 倾向**：先完成实测，若 cold 为主 **优先评估 A**，A 未点头前 **不得** 假装 stage 2 能测当拍生成 |

### 4.1.2 内存基线（双报 · 单通过线）

GGUF 权重 **GB 级**。「相对仅检索 ≤200MB」若 **基线 = 模型未加载**，第一次测 **必失败**；若 **基线 = 已常驻**，200MB 量的是 **边际生成开销**，不是 **为生成而加载模型** 的总代价。须 **事先** 写死：

| 基线 | 量什么 | 是否通过线 |
|---|---|---|
| **A · 冷机（模型未加载）** | 30 分钟计时专注会话：从 **未加载 GGUF** 到会话结束的 **RSS 峰值总增量** | **不设** ≤200MB 通过线；**必须报告**（透明披露「为本地模型付多少 RAM」） |
| **B · 已 resident** | 同会话、同机，模型 **已加载且 resident** 的前提下：生成试点相对「仅检索、同 resident 状态」的 **RSS 峰值增量** | **唯一通过线：≤ 200MB**（§5.4.3） |

**为何通过线只锁 B**：产品已决定承担 companion 常驻/加载成本时，试点只问 **再多一次短生成** 是否可接受；**不** 用 200MB 假装覆盖整包权重。

阶段 0 交付物 B · 一页说明：实测用 **A 与 B 各报一次**；阶段 2 判定 **只读 B**。

**阶段 0 收口**：交付物 A + B + 模型冻结表（§10）+ 法律范围 → **PO 书面认可**（可写在阶段 0 结论页或 PR 评论）→ 才允许阶段 1。

#### 5.4.1 志愿者闸（年龄不可验 · 可操作定义）

#### 5.4.2 延迟上限（生成臂 · **仅 `modelWarm=true`** · 阶段 0 锁定 quant）

**前提**：本节 **不** 约束 cold 开口；cold 一律 `fallbackReason=cold-start` 并回退（§4.1.1）。阶段 1/2 的 **p95 延迟与 §5.4.2 表只统计 `modelWarm=true` 的生成臂机会**。

从「抽到生成臂且 `modelWarm=true`」到「校验通过并允许展示」的墙钟时间；超时 **必须**回退检索，计 `fallbackReason=timeout`。**不得**先空白开口再等生成。

| 通道 | 上限（ms） | 依据（现网 UI） |
|---|---:|---|
| 结束低语 · Re-focus · Moment 类淡出 | **2500** | 展示后 `HOLD_MS` 约 **3500**（`MomentWhisperUI.js`）；须留余量给用户读句 |
| 到达后安静句 | **3000** | 卡延迟 **520ms** 后展示，持有约 **6200ms** |
| 专注中邀请 | **5000** | 邀请可见约 **10s**；仍须在 **5s** 内出可读句或回退 |

阶段 2 报告须按通道报 **p95 latency**；任通道 **p95 > 上表** → 该通道 **关生成臂**（见 §5.4.4）。

#### 5.4.3 内存增量上限（双基线 · 通过线只锁 B）

在 **同一台** stage 0 锁定机型（参考：**Apple Silicon 16GB** · Electron 宽屏）上，阶段 2 单次 **30 分钟**计时专注会话，**两种基线都须报告**（§4.1.2）：

| 基线 | 通过线 |
|---|---|
| **A · 冷机（模型未加载）** | **无** ≤200MB 线；只披露 RSS 总增量 |
| **B · 已 resident** | 生成试点相对同会话「仅检索、同 resident」的 **RSS 峰值增量 ≤ 200MB** |

超 **B** 线 → **全局**关生成臂（试点结束），不等同「用户不能坐」。报告须写清测量工具（`ps`/Instruments 等）。

#### 5.4.4 回退率上限与「生成臂无意义」

记 **生成臂机会** = 抽到 `arm=generate` 且模型 ready、试点旗标开、未 kill-switch 的次数。

| 指标 | 数字 | 含义 |
|---|---:|---|
| **单通道成功展示率下限** | **≥ 35%** | `checkPass=true` 且用户看见变体的次数 / 该通道生成臂机会 |
| **单通道回退率上限** | **≤ 65%** | 与上式互补（含 forbidden / length / empty / **timeout** / **cold-start**） |
| **无意义停臂线** | **> 65%** 回退 | 该通道在阶段 2 **立即停生成臂**（只留检索）；**禁止**为凑样本继续抽生成 |
| **全局停试点线** | **> 75%** 回退（四通道合计） | 阶段 2 判定 **成本关失败**；全局回到检索，不扩面 |

本地模型常需数秒；**cold-start 与 warm-timeout 须分账**（§4.1.1）。若 cold 为主，应走 **§4.1.1 分支 B 或 A**，**禁止**用 warm 延迟表硬跑 stage 2 再得出「全部回退」的伪结论。

#### 5.4.5 三问判据（在 §5.4.2–5.4.4 预算内）

| 问 | 预设判据（没有增量就停在检索） |
|---|---|
| **安全** | 违规展示数 = 0（相对 §5.1）；告警/人审升级不高于检索臂 |
| **可接受性** | 盲测成对偏好（生成 vs 检索）只作内部报告；**仅对成功展示率 ≥35% 的通道**解读偏好。点估计偏好 ≤50% 或样本过小 → **不扩面** |
| **成本** | 各通道 p95 latency、RSS 增量、回退率满足 §5.4.2–5.4.4；任一通道触发 **>65%** 停臂或全局 **>75%** → **关生成臂** |

**停做也是产品结论**：受限生成在你们场景里没有可测的安全-可接受-成本增量，就停留在 1 级检索。省下安全成本。
