# Task Brief · 冷启动「目标」问答最小验证方案

> **状态（2026-09-06）**：**approved · blocked** — 产品方向已采纳；**现在不实现**。硬前置：`task-cold-start-first-scene-audit.md`（冷启动第一幕 11 入口审计收口）。  
> **关联专项**：分散仲裁排查（冷启动第一幕）、Practice Identity（行为反射型身份 · 刀 4 · 未开工）

## 产品拍板（2026-09-06）

- **方向采纳**：首次冷启动可问 1 题「你今天想做什么？」，映射现有功能入口，当次会话可见效果。
- **现在不实现**：冷启动第一幕尚未审计收口；叠加新 gate 会扩大已知高风险面。
- **与 Practice Identity**：V1 两条独立信号、不落库、不污染 PI 行为数据源；PI 上线（`FROM_APP_TO_CULTURE.md` §13.4 刀 4）后再定义覆盖规则。

## 1. 背景

用户在冷启动首次打开 App 时，目前没有任何「目标/使用场景」自报环节。产品侧提出：是否应在首次冷启动加入一个极简问答，用于让系统据此做首屏/推荐的适配。

讨论结论：合理性成立的前提是**答案必须在当次会话内产生可感知的效果**，否则只是纯摩擦；且必须与已规划的 Practice Identity（通过行为观察反推身份，而非自报）明确分工，避免两套个性化机制互相打架。

## 2. 范围声明（明确不做什么）

- 不做多题问卷，只做 1 题单选。
- 不问「职业/生活状态」——职业到功能的映射不直接，价值不明确，本轮不做。
- 不新建独立的用户画像存储体系；答案作为轻量本地字段存储，后续如需扩展再议。
- 不在本任务中动 Practice Identity 的实现或触发逻辑，只做好「未来对接口」的预留。
- 不在冷启动第一幕 11 入口审计收口之前开工合并到 develop（见第 5 节依赖）。

## 3. 设计细节

**问题**：「你今天想做什么？」 / 单选，选项对应现有功能入口，而非抽象标签：

- 专注一会儿 → 首屏默认跳转 MicroRitual（时长用现有默认档位，不新增逻辑）
- 静一静 / 减压 → 首屏默认跳转 Sit with Yin
- 学习 / 工作 → 首屏默认跳转 MicroRitual，时长档位可指定为更长档（如 20 分钟档，具体档位由 Cursor 结合现有档位表判断）
- 只是看看（即跳过语义，作为等价选项而非隐藏链接，降低「被强迫选择」的感觉）

**必须可跳过**：「只是看看」本身即跳过态，选中后不触发任何默认跳转，走当前无问答时的原有首屏逻辑。

**生效方式**：选择结果只影响「首次会话首屏跳转/默认时长」，不影响其后任何会话——即这是一次性的冷启动默认值，不是持久画像字段。数据留存与是否要长期保留、是否要在设置里可修改，本轮不做决定，按最小验证先落地不落库（或只存 sessionStorage 级别，具体由 Cursor 结合现有存储层判断）。

**与 Practice Identity 的关系**：本问答的答案不得写入/污染 Practice Identity 将来使用的行为数据源；两者是两条独立信号，暂不融合。后续如需融合，须另开讨论，不在本任务范围内。

## 4. 验收标准

- 首次冷启动出现该问答，非首次冷启动不再出现。
- 4 个选项均可点击且各自触发预期跳转/默认值，「只是看看」选中后行为与当前无问答版本完全一致（可对照测试）。
- 不新增任何跨会话持久化的用户画像字段。
- 不触碰/修改冷启动第一幕现有 11 入口的仲裁逻辑，只是在其中新增一个纯展示层入口（须与冷启动仲裁现有 owner 确认新增入口不破坏既有 gate 顺序；插入位见审计清单 `cold-start-first-scene-audit-inventory.md`）。
- i18n：本轮仅 EN，zh/ja 占位 TBD（与此前 Confide 相关任务的多语言处理原则一致）。

## 5. 依赖 / 开工时机

**blocked · 等审计收口**。建议排在「分散仲裁—冷启动第一幕（11 入口）」审计收口之后再启动，原因：

1. 冷启动区域目前是已知高风险未收口区，现在叠加新入口会扩大排查面。
2. 收口后对冷启动的入口/仲裁顺序会有更清晰的模型，新增本问答入口时更容易判断插入位置且不易引入新的分散仲裁 bug。

**开工口令示例**：「开工冷启动目标问答」（须审计 Brief 状态为 `closed` 或 `audit-pass`）。

## 6. 风险与已知冲突点

- 摩擦风险：即使 1 题也占用首次冷启动的注意力，需要与「是否在体验到一次核心动作后再问」做取舍（本轮先按「开场问」设计，是否移到 Arrival Practice 之后可作为后续 A/B 议题，不在本轮拍板）。
- 与 Practice Identity 潜在语义重复，已通过「不落库、只影响首次默认值」降低冲突面，但仍需在两者都上线后做一次联合审查。
- 冷启动第一幕仲裁未收口前如提前实现，存在返工风险。
