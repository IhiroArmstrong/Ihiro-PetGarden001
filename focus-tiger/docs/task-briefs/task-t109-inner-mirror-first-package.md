## 0. 大白话

人在觉察一句里写下的话，默认仍不保存。只有自己点了「留下」，这句话才进电脑本机。攒够了，自己点开这一周，看见重复出现的事；不同意就改，改过的以后不再出现。点「忘掉」，原文和改口记录一起删掉。条数不够，就只说还不够，不编一个主题。

首包当天没有人有满一个月的留下，所以月回看不卡发布。打卡和倾诉原文这期不读。

## 1. 目标（卡住 12/8 的范围）

1. 同一张 Thought Drop 卡上增加「留下」。没点过 = 与今天一样，不存原文。  
2. 本机日志只存点过留下、且不是危机句的原文。  
3. 「忘掉」或关掉授权：原文与纠正记录一起真删；应用仍掌管的备份快照里也不得再留这些原文。  
4. 纠正用结构化记录 + 确定性闸。不能只靠提示词。  
5. 周回看与「攒完问一句」：用户点开才出。主题与次数用规则数。  
6. Moments of Change 只由用户自己点。禁止程序颁发。  
7. 三项验收写成会失败的测试：纠正后不再出现；无人格/进步判词；不够只说还不够。

## 4. 数据

建议键：`focus-tiger.inner-mirror.v1`。实现刀把这一行写进 `SHARED_RESOURCES.md`，并写明 **不在** 本地 Backup & restore 白名单、**不在** 练习云备份 v2 八 key、**不进** `buildWeeklyPayload` / T54 研究共修。

记录形状（实现可换字段名，不得换这四件事）：

- 留下的句子：id、原文、留下时间。危机句不得有这一行。  
- 主题：id、状态 `active` / `corrected` / `void`、规则键、用户替换句、纠正时间。  
- 改变时刻：id、用户自己的短句、标记时间。禁止没有用户点击就出现。  
- 授权：默认关。关 = 与忘掉同一条删除。

**真删的边界：** 忘掉时删除本键；若应用自己写过、且仍由应用掌管的备份快照里含本键，必须从那份快照里去掉。之后的导出不得再写入。用户已经复制到应用够不着的文件里的副本，不得写成「已经从全世界删掉」。

**条数（写死，改数字须改本 Brief）：**

- 窗 = 本机日历最近 7 天。  
- 窗内留下少于 3 条，或同一规则键少于 3 条 → 只显示固定句「还不够」，不出现主题句。  
- 主题句只许陈述规则已经数出的次数与规则键。模型最多把这组已锁定的事实写成观察式问话。本地模型不可用时，用代码填进固定模板，不现场编主题。

禁止句示例（方向锁已有）：「你变得更有耐心」「你在克服自卑」「回避型人格好转」。

## 8. 点击反馈（0–1 秒）

| 控件 | 点击后 0–1 秒内 | 持久化 |
|---|---|---|
| 留下 | 钮变为已留下，或明确失败（写盘失败要看见失败，不得无反应） | 挂起不可见（本地同步写）；成功 = 已留下；失败 = 钮回到可点并有一句没存上 |
| 忘掉 | 卡上第二层区域立刻空白 | 成功 = 空白且键已删；失败 = 仍看见原文并说明没删掉 |
| 纠正 | 该条标成「已按你的意思改过」 | 成功后再次打开不得再现旧观察 |
| 打开周回看 | 卡内展开这一块，或「还不够」 | 不写新原文 |
| 标记改变时刻 | 出现用户刚写的短句 | 成功才出现；失败不出现空徽章 |

不把这些点击登记成 `SILENT_BEHAVIORS`。
