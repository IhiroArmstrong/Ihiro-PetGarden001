## 3. Web 流式方案（B 刀锁定）

我认为最合理的是：**浏览器原生 `<video src="https://…mp4">`，让播放器自己发 Range**，不要在网页再 `fetch` 整份 ArrayBuffer。

为什么：R2 已支持 Range；MP4 若 moov 在前（faststart），首包即可解码；不必自写 MSE；整片 SHA-256 与边下边播互斥。

较弱做法：

- 继续整片下载再播 → 正是本刀要修的体验隐患。  
- 自建 MediaSource + 手工拼 fMP4 → 过重，Safari 坑多，本刀不做。

### 行为

1. 点课 0–1 秒：课页打开，状态「正在准备播放」（或等价 locale 键），**不是**空白。  
2. `canplay` / `playing`：开始出声画。**不得**等 `deliveryBytes` 全部到达。  
3. 缓冲中（`waiting`）：状态「缓冲中」；可用 `video.buffered` 显示大约进度（有则显示，没有也不许空白）。  
4. 失败：`error` / 无法解码 → 现有课内重试；**不弹窗**；**不**自动改播纯音频。  
5. **不做**整片 SHA-256。校验字段仍留在 catalog，供 Electron 使用。  
6. 不预下载、不后台拉下一课。  
7. 后台网络：本路径是用户点了才请求 → **不涉及后台网络**。

Safari / 手机：若直链无法起播，重试仍走直链一次；仍失败则课内错误态。**禁止自动**换成纯音频。保留用户主动点的「只听音频」按钮（`guided-meditation-audio-fallback`）。Web `<video>` **不得**加 `crossorigin`。

### 3.1 练习计入（B 刀补锁）

计入看**累计实际播放秒数**：只把连续 `timeupdate` 的正向小增量加起来；拖动进度条造成的大跳跃不算。禁止用 `currentTime / duration` 当「听了多少」。短课仍须实际播放 ≥90% 才记名义分钟。长课规则（实际播放满 3 分钟起、按实际整分钟计入、上限为片长整分钟）**已在 #1567 实现**；本刀补「拖动不计」单测，不重写长课公式。

## 4. Electron 方案（C 刀 · 已合 #1571）

1. **保留**整片下载 + 字节数 + SHA-256。不符则不挂播放源、删残片、课内重试。  
2. 缓存目录：`userData/guided-meditation/{lessonId}/{sha256}.mp4`（与 P0 spec 一致）。哈希已匹配则跳过写盘，直接播本地。音频用户点选后走同一套落盘，对象键用 `audioSha256`。  
3. 下载用可读流累计字节，对照 `deliveryBytes` / `audioBytes` 显示「12 / 27 MB」一类进度。同一课禁止第二条并发下载。  
4. 半途退出留下 `.part`，下次可 Range 续（若本刀实现成本高，允许第一版失败后整段重来，须在 PR 写明；不得假装已续传）。  
5. 自定义协议把媒体打成 JSON 报错 → **本任务不做**。  
6. Web e2e **不能**代替电脑版真机（§8）。  
7. **禁止**再引入第二个媒体根常量或第二张课程表。

## 8. Electron 真机验收清单（短课优先）

在 **打包桌面版**（不是浏览器 e2e）上：

1. 菜单看得到引导冥想；点短课。  
2. 下载期间能看见进度，不是空白。  
3. 校验通过后能出声画。  
4. 人为断网后再点同一课：已缓存应仍能播；未缓存应「需要网络」+ 可重试。  
5. 播到可计入规则后，练习日/莲花与 Web 同一套计入（短课实际播放 ≥90%；长课满 3 分钟起按整分钟。拖进度条到结尾不算听完）。

贴回：能播 / 不能播 / 卡在加载；有无进度；是否桌面版。
