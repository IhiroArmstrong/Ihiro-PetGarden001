## 0. 大白话

Yin 已经会记住你上次坐多久，倦的时候建议短一档，你不要某类提醒就少说几天。可是这些记事分散在好几本小本子里。这一份书锁 **读侧**：一本只存事实的本地账、所有入口只从一个读门拿默认。

开表前的高亮跟 **常用**（同一档手动选满 3 次，且落在时间窗口里）。没有常用就回退到上次。点「还是上次那个」或一键沿用当前高亮，**不算**学会了你。你声明倦了时，短一档压过常用。证明之前不说「越来越懂你」。

## 2. Resolver 契约（第一刀必须写进单测）

给定同一份本机存储，下列问法必须得到同一组答案（纯函数，不读 DOM）：

- `lastStoredFocusMinutes`（生偏好 / 「上次」）  
- `lastManualAnchorMinutes`（T58 锚点；规则不改）  
- `habitualFocusMinutes`（窗口内合格手动同一档 ≥3 次才有，否则 null）  
- `tiredSuggestsShorter`（沿用 T58：适应开且近 5 次结束倦 ≥3）  
- `highlightFocusMinutes`（**唯一**给芯片高亮 / T67 出示默认用的档）  
- `adaptationEnabled`  
- `latestEndCheckInLabel`  
- `workEndClock`

### 2.1 高亮优先级（写死，禁止再分散仲裁）

按序取第一个命中：

1. **倦短一档**（T58）：适应开且 `tiredSuggestsShorter` → `highlight =` 锚点下一档（不累计、下限 10）。**优先于常用。**  
2. **常用**：`habitualFocusMinutes` 非空 → 高亮常用。  
3. **上次**：有生偏好 → 高亮上次。  
4. **默认 10**。

T59「还是上次那个」**保留**，仍只陈述上次偏好是否存在，**不**改成说常用。两个信号都在，只有高亮跟常用（或倦时跟短一档）。

### 2.2 什么叫「合格手动选」（计入常用）

**计入**：用户点了时长芯片，且该档 **不等于** 当时 resolver 给出的 `highlightFocusMinutes`（即改写了高亮 / 没有一键沿用）。

**不计入**（否则会自我强化惯性）：

- 点 T59「还是上次那个」（若可点）或任何「沿用上次 / 沿用当前高亮」控件。  
- 点 **当前高亮** 那一档芯片（一键接受建议或接受上次）。  
- 没拨芯片、直接开始（T58 已有：不改锚点）。  
- 配方模板写回时长键（写侧可仍写生偏好；**不**当合格手动、不推常用）。

合格事件须带时间戳，供窗口裁剪。

### 2.3 常用时间窗口（默认，点头已锁）

**默认：最近 12 次合格手动选。** 同一档在这 12 次里出现 ≥3 次、且该档次数**严格第一** → 该档为常用。并列（含四档各 3 次）→ **没有常用**，高亮回退上次。禁止「再并列取较新」（噪声下会来回翻，像记错了）。

窗口用「次数」不用「自然周」，避免练得少的人永远攒不满、或旧习惯按日历冻住。若以后要改成「近 28 天」，须另改 Brief。

窗口外的旧点击 **不**再支撑常用，避免换习惯后高亮停在旧值。

### 2.4 包装、不重写

第一刀把现网三条时长读法 **收进同一函数**，不另起第三套分钟算法：

- 生偏好 `loadPreferredFocusDurationMinutes` → resolver 的「上次」  
- 适应高亮 `resolveAdaptedFocusDurationHighlightMinutes` → 作为倦短一档的 **实现委托**（数字仍 T58）  
- T59「有没有存过」→ 仍只问生偏好是否存在  

芯片高亮、T67 `offeredDefaultMinutes`、配方写回后的下次出示，都只读 `highlightFocusMinutes`。禁止 `sittingSessionPromptHost` 再读生键当高亮。
