## 0. 大白话（给拍板用）

Sit / Ground 能答对，不是因为模型「懂产品」，而是短答来自**现在界面上真实存在的字**。  
Epic、测试计划、PR 适合提醒「还有哪些主题可能漏了」，**不能**当说明书原文。  
规模化做法：脚本先圈定「代码里还活着的功能」→ 只用 locale / 规则源码起草 → 机器能核对的先核对 → 人只抽查语气有没有越界。  
给团队看的内部手册可以先用过程性文档汇总；给阿寅念的条目必须重新走上面这条路。

**目标**

- 不做人可浏览的对外帮助中心。

## 三、核心判断：能规模化的是「权威当前源」

Sit / Ground（0001 / 0002）可靠，因为原料同时满足：

1. **当前性** — locale 与菜单树 = 现在跑出来的样子  
2. **低歧义** — 一个 key 一段确定文案  
3. **可脚本验证** — key 是否仍被引用、入口是否仍可达

Epic / Tracker / PR **不满足**这三条：同一份里混着已上线、已改设计、已砍掉。那种偏差是**系统性的**，抽 5 条查不出另外 10 条同一类错。

因此：过程性文档只做**候选主题清单**；正文起草只信权威当前源。

## 四、四步流水线

### 第一步 · 自动圈定「确实已上线」

不用人读 Epic 猜。脚本回答：

- locale key 是否被非死代码路径引用  
- 对应 feature flag / 查询串关闸在生产默认是否开启（例：`?focusCoins=0` 是关闸，默认开）  
- **以后**若复用 Playwright / Electron：遍历菜单，产出「真实可达路径清单」

输出：存活功能/入口表（locale key 集合 + 代码位置）。找不到权威源的候选 → 标「需产品确认」，**不生成条目**。

### 第二步 · 只用权威当前源起草

| 允许 | 禁止当正文来源 |
|---|---|
| `src/locales/*.json` 现网字符串 | Epic「我们打算……」 |
| 规则/配置源码（账本、备份 whitelist、菜单 census） | Test Tracker 测试步骤 |
| 第一步的可达路径清单 | PR 的计划改动叙述 |
| 与源码对齐的产品 SSOT（仅用来约束禁写数字/禁词，如 `FOCUS_COINS.md` 的焦虑禁令） | 未上线草案、失败复盘 |

起草约束：只能引用喂进去的片段；产出 **待审草稿**，不直接入库。短答必须可对用户原样念（检索接线 Q1）。**禁止**把日封顶、单价、阈值等会随运营调整的数字写进正文——过期后等于撒谎，与「念内部手册原文」是同一类病；只指路到入口 / 规则本身。

### 第三步 · 分级核验

| 类型 | 方法 | 人？ |
|---|---|---|
| 引用有效 | locale key 仍存在且非空 | 否 |
| 与权威源一致 | 按钮名/路径能在原料里找到 | 机器初筛；对不上标红 |
| 语气越界 / 编步骤 / 念引导语 | 抽查 | **是**（唯一必做人的块） |
| 权威源信息不足 | 标「待产品确认」，不入库 | 只处理机器筛出的少数 |

抽查只在前两步收窄之后才有效。

### 第四步 · Epic / Tracker / PR 只发现缺口

产出标题级候选（「寅币机制」「备份里有什么」），每条回到第一步。  
禁止把内部手册或 Epic 段落轻改后写入 `product-knowledge-base.md`。

## 六、对照已发生的两类病（不是同一修法）

### 6.1 缺问法（低风险，可批量）

例：口测「备份会备份哪些数据」未打到已审的 0015。  
事实没变，只扩已通过条目的检索关键词 / 问法门闩（怎么/在哪 **以及** 哪些/会不会/包不包含）。  
**不重审正文。** PO 抽查关键词是否仍对准原条。

Sibling 旁支已做一部分：产品问门闩纳入「哪些/包不包含/装了什么」；0015 补范围词。本 Brief 把这收成**可重复步骤**，不把那次修复重开一遍。

### 6.2 缺内容 vs 根本没上线

例：口测「How to get more focus coins?」曾落到 generate「I do not know」。

**第一步结论（本仓静态核对，2026-09-22）**：寅币**已上线**，不是 Epic 空想。

| 角色 | 位置 |
|---|---|
| 发点/封顶规则 | `src/core/focusCoinsLedger.js`（单一账本模块；award/redeem/store 消费它） |
| 产品禁令与对外名 | `FOCUS_COINS.md` + `task-focus-coins.md` |
| 关闸 | `?focusCoins=0`（默认开） |
| 入口文案 | locale `focus_coins.*` / Yin's Collections |
| 可念短答 | `KB-FUNC-0018`（已通过；catalog 已含 `focus coins`） |

因此：要补的是问法/构建是否含 0018，**不是**从 Tracker 再编一套规则。短答禁止念日封顶数字（与 0018 已锁口径一致）。

若某主题在代码里找不到对应源 → 「I do not know」可以是对的，标需产品确认。
