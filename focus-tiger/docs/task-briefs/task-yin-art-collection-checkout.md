## 这一刀做

1. 独立入口和面板，名字用 **Yin's Art Collection**。不放进阿寅的珍藏，不放进请茶。
2. 五张卡，点开详情：图、名字、一句故事、价格。
3. 购买走**单独结账**。请茶成功不等于拥有这张画。沿用现有第三方结账，不自建一套支付系统。
4. 记账顺序：付款成功 → 服务端记下可拥有 → 再记「已拥有」。本地只做缓存，不能单独当成付款凭证。
5. 已拥有的作品显示获得日期。
6. 登录后能恢复已拥有。未登录时不能把本机缓存说成已经买下。

点购买后，1 秒内应看到结账开始打开，或一句清楚的失败说明。成功后看到已收藏和日期。失败时仍是未拥有。挂起时不要写成失败。

## 这一刀不做

- 庭院摆放、打包、送礼、限量编号、023/500、倒计时、售罄、实体优先权。
- 数据模型里的 chain / contract / token。
- 点一下就在本地记成已拥有。
- 用请茶、寅币或练习成绩换这些图。
- 卖 Focus、寅币、成长或练习解锁。
- 把另一组清供卡面图（鞍马、博山炉等）当成这一批商品。

生产环境的付款服务上线，仍要另说「部署」，不因本文点头就自动部署。

## 冲突扫描

对照场景 AC（阿寅的珍藏）和场景 Q（请茶）。

- 强度：次级入口，不插进完成庆祝。
- 人设：卖的是画，不是更专注。
- 职责：与珍藏、请茶分成三个入口。无冲突的前提是购买不进那两个面板。

## 验收

- 从珍藏抽屉和请茶进不去这五件的购买。
- 五件之外的图不出现在这个货架。
- 付款成功之前，界面不是「已拥有」。
- 付款成功之后，能看到获得日期。
- 换设备并登录后，已拥有的还在。
- 断网或结账失败时，不会多出一件已拥有。
