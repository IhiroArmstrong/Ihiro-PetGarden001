## 一句话目标

宽屏 ⋯ 和窄屏抽屉点某一行时，**只查一张表**（目录里的 `proxy → 处理函数名`），不再各写一条 `if (key === '…')` 链。漏接一项必须在单测里红，不能靠 `handlers.onX?.()` 悄悄跳过。

## 背景

根因 **R1**：同一菜单项要在目录、宽屏分派、窄屏分派、`main.js` 处理函数各写一遍，漏一处不报错。#1136 扇形/语音、#1138 Art Collection 就是这样。转发层已在 #1138 改成整包透传。宽/窄两条 `if` 链还在。

A1 只锁「点了之后看得见结果」。A2 改接线方式，让新行不必再抄两份分派。

## 范围（in）

- 在 `idleChromeOrchestration.js` 的次级目录行上声明稳定的 `proxy → handler` 名（或等价字段）。  
- `WideIdleMoreMenu.js` / `NarrowIdleShell.js` 的目录项点击改为查表；**删掉**这两条按 `key ===` 的次级菜单分派链。  
- 单测：`listSecondaryChromeEntries` 里每一个 `proxy` 都有对应处理函数；缺一行即失败。  
- 锁定仪式行、账号占位行：查表后仍不调用处理函数（与 A1 `locked-row` / `static-row` 一致）。  
- 合入后 A1 的 wide + narrow 全量可达 e2e 必须仍绿。

## 范围（out）

- **不**做 A3（全仓其它平行名单）、A4（开发模式缺失即 `throw`）。  
- **不**改 Confide 是否因会员解锁出现（仍等 PO）。  
- **不**改 Support / Stripe 付款入口、已购淡化、玻璃卡 z-index。会员菜单行仍只打开 `#yin-membership-card`。  
- **不**重做菜单外观、分组、文案。  
- 首页三颗球 / Sit 等非次级目录 CTA，除非它们已经走同一 `data-proxy` 分派且搬表是同一刀的最小必要。

## 点击反馈（0–1 秒）

与现网同一结果：点目录行后，对应面板/扇形/外链出现。本刀不改「出现什么」，只改「怎么找到处理函数」。查表失败时：**开发/测试**必须失败可见（单测红）；生产不得把菜单一关当成功（具体报错形态可与 A4 分刀，本刀至少不得 `?.()` 静默）。
