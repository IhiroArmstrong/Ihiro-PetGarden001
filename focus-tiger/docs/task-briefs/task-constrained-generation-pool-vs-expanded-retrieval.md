## 2. 评估稿漏了什么（必须写进本页）

[#1531](https://github.com/IhiroArmstrong/Ihiro-PetGarden001/pull/1531) 已合 develop。PO 2026-11-02：评估方向对，探针局限标注诚实，冷热表与现网卸载一致；下列三点评估稿当时没写。本页为补丁，**不**假装评估稿已含这些约束。

### 2.1 结束低语：会话槽位，没法预先生成完整句

现网结束低语（Rise 且 ≥30s）是 **观察分钟句**：locale 键 `SESSION_END_OBSERVED_MINUTES`，模板含 `{minutes}`，开口时由 [`sessionEndObservedDuration.js`](../../src/core/sessionEndObservedDuration.js) **确定性**填入本场实际分钟。

| 事实 | 含义 |
|---|---|
| 分钟数在 **专注结束** 才存在 | 到达后、点 Sit **之前** 填池时，这个数字还不存在 |
| 池只能存 **带槽位的模板** | 禁止让模型在开口时填数字（慢、不稳定、可能胡编） |
| 禁词校验必须跑在 **填完槽位后的最终字符串** | 入池时只扫模板不够：填入「90」或其它数字后仍可能撞表。这一步 **不用模型**，成本低 |

Moment 低语（Reflection 打开时按内部标签选键）同样：**标签名不进界面（C-09）**；若将来个性化复述用户选过的觉照标签，也必须是 **代码填槽 + 模型只管措辞骨架**，不得把内部状态名编进可见句。

评估稿 §4.4 写「入池后再展示、开口不再二次校验」——对带槽位通道 **不成立**。实现若仍做池化，须改成：

```
空闲：模型只产出带槽位的模板（或无槽位的纯变体）
  → 模板过禁词表；不过则丢弃
开口：代码填槽（分钟 / 已审标签短名等）
  → 最终字符串再跑同一张禁词表
  → 不过则回退现网固定句
```

### 2.2 填池窗口可能比「到达后、Sit 前」短

评估稿建议窗口：**到达之后、点 Sit 之前**。现网约束：

1. Sit 一开始 → `setFocusing(true)` → **立即 unload**（无 60s 宽限）。  
2. 填一次池 ≈ 加载 **p50 3029 ms / 约 2.5GB RSS**（#1531 探针，**只含加载**）+ tokenize / 生成。  
3. 很多用户到达后 **几秒** 就点 Sit。没有「到达到点 Sit」的间隔分布，就 **不得** 承诺池空率通过线。  
4. 每次会话前一次 2.5GB 加载再卸载，会推风扇、发热、耗电。产品定位是 **安静陪伴**，不是每次坐下前先热一阵机器。

若仍写路径 A 的 B 类 Brief（本页点头 **且** 仍选池化之后才允许），Brief **必须**先加两条，缺一不得开工：

- **实测** Arrive 完成 → 点 Sit 的间隔分布（分位，至少桌面宽屏）。没有这组数 → **禁止**写死池空率线。  
- **电池供电或低电量** 不填池；**风扇 / 发热** 列为停臂判据之一（与池空率并列，不是附注）。

### 2.3 预生成池 ≈ 扩大后的人工审核固定句库

一个有限、已校验、取用即删的内存池，**功能上**就是更大的固定句库。差别只在句子是：

| | 本机池化生成 | 离线生成 + 人审扩库 |
|---|---|---|
| 谁编句 | 用户机器上的同一 GGUF | 离线编、编辑审、进仓或 overlay |
| 运行时内存 / 发热 | 每次填池约 2.5GB 加载 | **无**（开口只检索） |
| 池空 | 窗口不够就回退 | **无** |
| 审核强度 | 主要靠字面禁词表 | 人审，能抓换说法漏网 |
| 下发 | 本机会话内 RAM | 现有 **句包 overlay**（Quiet Line / Confide 句已走这条管道） |

本机生成 **真正独有** 的价值，只在 **带用户上下文的个性化措辞**（例如复述用户自己点过的觉照标签）。这类句子一样要靠 **槽位**；模型只管骨架，数字和标签由代码填。

这会改 **阶段 2** 的对照设计：若生成臂对比的是现网每通道只有几句的小库，测出来的「更好听」多半是 **新鲜感**，不是生成本身。**对照臂必须是「扩充后的检索库」**（同通道、同语气、条数与生成臂候选同量级、同样人审过），否则结论没有意义。

现网条数（地面真相，禁止夸大「已经很大」或「几乎没有」）：

| 通道 | 现网可见句规模（约） |
|---|---|
| 结束低语 · 观察分钟 | **1** 条模板 + `{minutes}` |
| 专注中邀请 | 暂停问句 **1** + 延长问句 **1**（`awaken-invite.json`） |
| 离开后再聚焦 | **3** 条 `REFOCUS_ACKNOWLEDGE_*` |
| 到达后安静句 | Moment 键 **1** 条 `MOMENT_WHISPER_ARRIVE`；Calm Action Arrive 另有 CMS 日池（比上三通道大，但仍是检索，不是本机预生成） |

## 3. 三条路

| 路 | 开口瞬间做什么 | 本机加载 GGUF？ | 池空 / 发热 | 审核 | 与原则 |
|---|---|---|---|---|---|
| **A · 池化本机生成** | 取已校验模板，代码填槽，再扫禁词 | 填池时要；专注中不得常驻 | 窗口短 → 池空率可能高；风扇/电 | 字面表为主 | 顶 Never-Cloud 与无原文，但 **顶低配友好 / 安静** |
| **R · 离线扩库 + 人审** | 检索已审句（可 overlay 热更） | **不要**为这四通道加载 | 无池空 | 人审强于字面表 | Never-Cloud、本机无原文、低配友好、overlay 已有 |
| **B · 到达句缩范围** | 其它三通道继续固定小库；只评估/保留到达 | 到达前仍可能热，但评估稿已预见当拍也不稳 | 范围最小 | 不变 | 当 A 与 R 都暂不做时的退路 |

## 4. 本机生成相对扩库多出什么？值不值得？

必须先回答这一句，再决定要不要写 B 类实现 Brief。

| 声称的增量 | 扩库能否覆盖 | 池化是否多出来 |
|---|---|---|
| 句子不那么重复 | **能**（把每通道从 1–3 条扩到几十条已审句） | 否，只是换地方编 |
| 语气贴契约 | **能**（人审比禁词表强） | 否 |
| 不发版改句 | **能**（现有 overlay） | 本机池重启即丢，overlay 更稳 |
| 复述本场分钟数 | **部分能**（扩库仍用 `{minutes}` 槽，代码填） | 模型填分钟 **不允许** |
| 复述用户选过的标签 / 本场上下文骨架 | **弱**（离线句不知道这个人今天点了什么） | **是**：这是本机生成几乎唯一站得住的增量，且仍须槽位 + 最终串禁词 |

**若答案是「主要是新鲜感」**：**不值得**为四通道付池空率、2.5GB 加载、风扇和电。走 **R**。

**本机生成留给很小一块**：只在开口时 **已经知道** 的上下文（分钟、用户点过的已审标签短名），模型只改骨架，代码填槽，最终串再扫禁词。这一块范围默认 **不做四通道全覆盖**；未点头前 **不写** 实现 Brief。

## 5. 我认为最合理的

**先走 R（离线扩库 + 人审），本机生成缩到「带槽位的个性化骨架」且本回合不实现。**

为什么：四通道里三通道几乎全冷，填池窗口可能只有几秒，安静陪伴不该每次坐下前热一遍 GPU；扩库能用 overlay 下发，没有池空，审核更强。对照臂若仍是现在那几句，阶段 2 测的是新鲜感。

**B（只留到达句）** 仅在「连扩库也不做、只承认当拍生成不可行」时用。弱于 R：到达句现网已有 Moment 键 + Calm Action 日池，缩范围不增加新鲜感，只减少风险面。

**A（四通道本机池）** 仅当 PO 书面认定「个性化骨架」的增量 **大于** 发热 / 电 / 池空，并先交出 Arrive→Sit 间隔分布之后。现在没有这组数，**不得**写 A 的实现 Brief。
