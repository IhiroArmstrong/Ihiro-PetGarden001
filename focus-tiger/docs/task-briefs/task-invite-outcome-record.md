## 0. 大白话

Yin 问过「要不要停一下」之后，现在只知道邀请出过，不知道你是点了、关了，还是没理。这一步只把这三种下场记在本机，方便以后少问。这一步本身不让 Yin 少问，也不多问。

## 1. 目标与非目标

**目标**

1. 每一条专注中邀请有一个本机下场：`accepted` / `dismissed` / `ignored`。
2. 只记种类、下场、时间。不记 Yin 说了哪句，不记倾诉原文。
3. 给定一段历史，记录结果是确定的，用单测锁住。

**非目标**

- 不改变冷却、不暂停某一类邀请、不加新邀请。
- 不上传。不进练习云备份。
- 不记离开后再聚焦提示（场景 B）的下场。那条先保持现状，避免第一刀把两种开口混成一类。
- 不改倾诉生成。专注中仍不开倾诉。

## 2. 记录

| 字段 | 内容 |
|---|---|
| 种类 | 现有编排里的一类邀请（停一下 / 再坐一会 / 长坐舒展）。实现时对照 `InterventionOrchestrator` 已有种类，不新造种类名给用户看 |
| 下场 | 点头 = `accepted`；明确不要 = `dismissed`；到时自己消失 = `ignored` |
| 时间 | 毫秒时间戳 |

建议上限与 **T52** 一样量级（数百条，超出丢最旧）。写盘失败则这次不记，邀请照旧消失。
