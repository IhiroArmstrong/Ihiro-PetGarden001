### 1.1 分档（全局）

| 档 | 含义 | 纯语音怎么走完 |
|---|---|---|
| **A 直接执行** | 可逆或低伤害；开始后 **5 秒内**可用取消口令停下 | 命中 → 立刻做 → 语音+文字播报。取消见 §13。 |
| **B 复述确认** | 写盘/外发文件/改多项资料；听错代价高 | 命中 → **先复述将做什么** → 用户说 `Yes / Please do it / Go ahead` 才执行；`No / Cancel / Stop` 放弃。不得要求点按钮。 |
| **C 严格确认** | 钱、清空记忆、不可逆删除、改账号 | 复述 **具体后果** → 用户须说产品指定的确认句（如 `Yes, forget everything`），与取消句成对；两轮内未说清则回到倾诉/静默等待，**不**执行。 |

**分档规则（禁止歧义）**：严度只许 **A ＜ B ＜ C**。备份停在 B：必须先复述再 `Yes / OK`，禁止听完就写盘。付款、覆盖恢复、忘掉全部停在 C：比备份多一轮指定确认句，不得降到 B 或 A。C 比 B 更严，不是「备份不得比 C 更轻」。

**适合语音办理**：一件事、结果可播报、不必看复杂版面。  
**需要确认**：适合办，但听错会写盘或寄出。  
**不适合（本阶段）**：必须盯着画面挑一张图、拖时间轴、在小格子里精确定位；不是永久不做，是未设计「语音选第几项」之前不做自动执行。

## 2. 入口形态

**计划 →** 两入口同一封闭指令集、同一确认档、同一 Never-Cloud。  
**现状 →** Confide 有 Speak to type；时长板/Rise 有命令麦；**没有**称呼词通道，也没有独立「请阿寅办事」入口。Operating 仍是方向锁。  
**还差 →** 第一刀称呼词；第二刀独立入口（**仍是 Yin 倾听**，不是无脸操作台）。  
**下一步 →** 按已拍板并存实现；独立入口位置仍待第二刀设计（优先挂既有 Preferences / 不新开 z 层则先改本 Brief）。

**推荐（已拍板，此处只写理由）**：并存。称呼词让「正在倾诉的人」不必换地方；独立入口让「我是来办事的」不必假装谈心，并给读屏/系统语音控制一个稳定控件名。

**独立入口（第二刀）语义（分析师选项 A，补录）**：进了这个入口，**每一句都按指令理解**，不再走倾诉桶。未命中封闭集 → 语音+文字请用户再说要办哪一件（仍禁止「不能做」能力羞辱），**不**把这句话当 Confide 倾诉存记忆。称呼词捷径则相反：未命中回普通 Confide。两入口同一封闭集、同一 A/B/C。

## 3. 解析方式

**计划 →** STT（本机）→ 安全层 → 称呼词门闩 → **封闭指令集**（关键词/句式规则 + 已有 embedding 近义排序）→ 仅候选集内才允许本地模型兜底 → handler。  
**现状 →** 专注命令 = 规则，不调陪伴模型。倾诉 = 路由 + 可选 L3。Speak-to-type 词表把 `Ian / Ean / Iain` → Yin（**不是**称呼词已验证样本，见 §8）。**故意不改** `in / yen / inn`。低配机隐藏本地 AI 入口，STT 仍可用。1.7B **最弱的是语用推断**，故「算不算指令」**禁止**交给它。本机 helper（`macos-speech-helper.swift`）成功 JSON 只有 `transcript` / RMS / bufferCount，**没有** `confidence`。Apple `SFSpeechRecognitionResult` 的 segment confidence **现网未读、未下发**。  
**还差 →** 指令封闭集与称呼词状态机；embedding 近义仅作**候选排序**，不得发明集外工具。  
**下一步 →** 第一刀：规则 + 词表容错。**命中判定 = 封闭集规则匹配，不是 STT 置信度门槛。** embedding 与 LLM 兜底等本地模型可见且 PO 另口令。

| 设备 | 指令如何仍可用 |
|---|---|
| 本机陪伴模型可见 | 规则优先；不确定时 LLM **只许**在封闭候选 JSON 里打分；打不出则当未命中 → 回倾诉 |
| **≤8GB、本地 AI 入口已隐藏** | **照常**：macOS 本机听写 + 规则。不出现「先下载模型才能备份」。无 LLM 兜底时宁可不执行、回倾诉，也不云端解析 |

禁止云 STT、禁止 `麦克风 → 云 LLM`。

## 4. 与现有路由的优先级

**计划 →** 固定先后，避免倾诉句被当成指令、也避免危机句被称呼词吃掉。  
**现状 →** `Safety → 在场/边界 → 情绪桶 → CI 白名单 → KB / L3`。FORGET 与 BOUNDARY 双命中时 FORGET 赢（现网）。Voice Command 与 Confide 组件分离。  
**还差 →** 在 Safety **之后**、倾诉桶 **之前**插入称呼词门闩。  
**下一步 →** 实现时把顺序写成单测表，禁止用症状名单堆「像指令的问法」（`R-Confide-No-Symptom-List`）。

```text
1. 安全层：危机 / 边界 / FORGET（含「Hi Yin, please forget…」）
2. 称呼词门闩（仅通道；未称呼则根本不看指令集）
3. 封闭指令集（命中才执行；未命中 → 4）
4. 既有 Confide：在场 → CI 只读/Forget 一条 → KB → L3 / 模板
```

**倾诉误判防线**：

1. 无称呼词 → 当倾诉（即使含 backup 单词）。  
2. 有称呼词但未命中封闭集 → **原句进 Confide**，不说 cannot / I can't do that。  
3. 带情绪、无 please/can you 办事骨架 → 不进指令集。  
4. 指令原文不写记忆、不进 `turns` 倾诉学习。

## 5. 执行与反馈

**计划 →** 办事路径每步 **字 + 声** 都要有（分析师：不能只靠视觉）。复用本机系统播报引擎，**不**跟「专注结束 Voice announcements 默认关」走——与倾诉回复朗读同一待遇：开关关着也要念指令复述/成败。危机转介句仍不朗读。  
**现状 →** 倾诉回复可朗读（不受该开关影响）；专注结束播报默认关。命令失败现为红字、无 TTS。备份走菜单，无语音复述。  
**还差 →** B 档复述稿、成功/失败/未命中重问、与叠层/专注态的关系。  
**下一步 →** 第一刀接备份三态 + 语音确认；播报复用系统 TTS，不新引擎。

| 状态 | 0–1 秒用户感到什么 | 随后 |
|---|---|---|
| 听清且命中 B | 文字出现复述句，**同时念出**（指令路径必声） | 等 `Yes / OK` 或 `Cancel`（纯语音） |

| 专注中 / 仪式中 | 不打断计时；短句「坐完我们再备份。」（不是硬拒绝能力，是延后） | 指令不执行 |

1. 用 §12 推荐的按键说话（或系统语音控制点按「说话」口令）开始听。  
2. 说一句称呼 + 备份（不要用开发集原句照念也可以）。

4. 说 `Yes` → 备份开始并完成 → 听到/看到成功。  
5. 再走一遍，复述后说 `Cancel` → **不**写出新备份。

8. 说 `Hi Yin, please` + 封闭集没有的事 → 普通 Confide 回复，无「不能做」。

## 12. 免点击启动

**计划 →** 完全点不了的人也能开始一轮听。  
**现状 →** 所有麦都要先点 🎙。无全局快捷键（Voice Command Brief 曾写 V1 不做）。无常驻唤醒。**专注进行中**：结束句麦在 Rise 旁边，同样要点 🎙；按键说话**现网不存在**，因此纯语音用户**不能**只靠快捷键说 `Rise` / `I'm done`。  
**还差 →** 按键说话（含专注态路由）、无障碍名、唤醒词评估。  
**下一步 →** 第一刀做按键说话，并补专注中路径；唤醒词只写代价，不实现。

| 方案 | 能否零点击开始 | 隐私 / 电 | 第一刀 |
|---|---|---|---|
| **按键说话快捷键**（推荐） | 键盘/辅助开关触发 = 开始听，松手或再按 = Stop（与现网 Stop 同语义）。Stop 后转写**自动提交**指令通道，不再点发送 | 仅按住时开麦 | **纳入第一刀** |
| 系统语音控制 / 读屏点「说话」 | 控件有稳定无障碍名与口令，如「Speak to Yin」「Ask Yin to help」 | 跟系统；App 不常听 | **纳入第一刀标签**（不自研第三套听写） |
| 常驻「Hi Yin」唤醒 | 真正零按键 | **一直听**；误唤醒；耗电；与 Never-Cloud 仍可本机，但心理负担大 | **只评估，不进第一刀** |

**我认为最合理的**：第一刀用 **按键说话 + 无障碍名**。常驻唤醒等免点击路径被真实用户抱怨「还是要按键」再开。

**说完即提交，确认窗自动开（PO 2026-10-17 点头写死）**：

- 按键说话结束（松手或再按）后，转写**自动提交**给指令通道。只能开口的人不必再点发送。
- B 档复述念完后，**自动打开 5 秒**收听窗，听 `Yes / OK / Please do it / Go ahead` 或 `No / Cancel / Stop`。不必再按一次快捷键。
- 5 秒内没听清、或超时：按 **取消** 处理，不写盘。与「沉默不得开始备份」同一条。

**Space vs 可重绑组合键**：分析师提过 Space。Confide 输入框里 Space 是打字；系统语音控制也常用 Space。默认 **不**抢 Space。默认建议 `Control+Shift+Y`（须可在系统快捷键里改成 Space 或其它，方便外接按键）。未获麦克风权限：语音+文字说明去系统设置开，不假听。

**系统语音控制范围**：第一刀 **Electron · macOS** Voice Control + VoiceOver 标签。Windows 语音访问 / 其它读屏：**后排**，随 Windows 壳另 Brief，不挡 macOS 第一刀。

**专注进行中的按键说话（PO 第 2 点 · 现网缺口，第一刀必补）**：

| 问 | 答 |
|---|---|
| 现网按键说话能否唤起命令麦说 Rise / I'm done？ | **不能。** 没有按键说话；只靠 Rise 旁 🎙。 |
| 第一刀补什么？ | 同一快捷键（默认 `Control+Shift+Y`，可重绑）在 `FOCUSING` 时打开**现网结束句**听写，接到 Slice 3 解析：`Rise` / `I'm done` / `End focus` = 点 Rise。单独 `Stop` / `Cancel` 仍**不**结束这场坐。 |
| 与备份指令的关系 | 专注中说备份仍延后（§5）；说结束句则走 Rise。路由看封闭集，不看「用户是不是想办事」。 |

## 13. 取消口令

**计划 →** A 档已开始后，用户说 `Cancel / Stop / Never mind`（及后续中文另 Brief）须尽快停。B/C 在确认前同一口令 = 放弃，不执行。  
**现状 →** 专注命令把单独 Stop 当拒绝结束；备份无语音取消。语音开坐后的 5 秒 Undo **只有点按钮**（`#voice-command-undo-toast` / `[data-testid=voice-command-undo]`），没有对应口令。  
**还差 →** 取消与 Rise 分家；备份写盘中可中断点；A 档 Undo 的语音对等。  
**下一步 →** 第一刀：确认前 Cancel 放弃；写入中 Cancel 尽量停并删除**不完整**新文件，不回滚旧备份；A 档 5 秒内 Cancel = 同一撤销 handler。

| 操作 | 开始后还来得及取消？ | 档 |
|---|---|---|
