## 0. 大白话

对比已经点头：这四条陪伴短句先不要在本机现编，先把每条路上的固定句子加一点、审完再发出去。本页只写怎么加、加几句、谁审英语和日语、怎么过检查、怎么下发。屏幕上的句子现在还是原来那几句。本页通过 **不等于** 可以开始写新台词，也 **不等于** 可以开阶段 1。

扩库有成本。现在没有真实用户，也还没人抱怨「老听同一句」。所以第一刀只扩到每条通道 **8–12** 句（有子类型的 **按子类型各数**，见 §2.1），并规定同一人连续几次不要撞同一句。一次性写几十条，审核贵，语气也容易散。

**诚实边界**：本刀验收只有「句子过检查、审完、下发规格锁死」——**没有**「用户感觉好了」的度量（尚无真实用户）。汇报里 **禁止** 写成「提升体验」；只写内容与审核流程建设。有了用户再补观察。

## 3. 不重复取用

线上还没有真实用户；新鲜感用小库 + 取用规则先挡住，不靠堆句子。

| 项 | 锁 |
|---|---|
| 粒度 | **同一用户 · 同一通道 · 同一子类型（有则分）· 同一正式语言** |
| 规则 | 连续 **N** 次开口 **不得** 再抽到刚抽过的那几句 |
| **N** | **`⌊该子类型可见条数 ÷ 2⌋`**（取半，向下取整）。例：8 条 → **N=4**；12 条 → **N=6**；4 条 → **N=2**。禁止 `min(7, 条数−1)`——8 条时 N=7 只剩 1 句可选，等于固定循环 |
| 池空 / 条数 &lt; 2 | 退回现网冻结表那一句；不得为凑 N 现场生成 |
| 槽位句 | 去重按 **模板 id**，不按填完 `{minutes}` 后的最终串（否则「坐了 12 分钟」和「坐了 13 分钟」会被当成两句而实际是同一骨架） |
| 存储 | 只记 **模板 id 环**（本机）；**禁止** 记生成原文或倾诉原文 |
| **本机键（B 类 Brief 锁定名）** | 建议 `focus-tiger.companion-channel-recent-ids.v1`（实现 Brief 可改后缀，须 PO 点头）。**必须**进 [`FOCUS_TIGER_LOCAL_STORAGE_KEYS`](../../src/core/focusTigerUserDataClear.js)（「删除所有数据」白名单；漏登则 `localStateKeyLiteralScan` 红，T60 同类教训）。**不进** T54 研究分享白名单。**不进** 练习云备份 / 本地 Backup 导出 |
| 实现落点 | 将来 B 类 Brief 指定；本页不改 `src/`。可对照现网日签 `recentIds` 精神，**不得** 和日签 / Quiet Line 混用同一把锁 |

将来若真有「句子重复让人腻」的用户反馈，再开第二刀扩库，不在本刀预支。

## 4. 审核人（英语 · 日语）

产品对外只声称 **英语和日语**。人审是 R 相对本机池化的核心优势。审核人必须能判断 **观察语气**（观照、不催、不诊断），不是只会对照字面或跑禁词表。

**C-11 诚实**：对外写「人审」= 有 **点名** 的母语/近母语审稿人签字。只有作者 + AI 预检、未经母语审稿 → 须如实写 **「作者 + AI 预检，未经母语审稿」**，**禁止** 写成「人审」或「已审」。AI 预检可做初筛，**不能** 顶替母语审稿。

### 4.1 英语闸

1. 说明书或 B 类 Brief **点名** 英语审核人（PO、指定审稿人、或书面委托编辑）。  
2. 每条英语新句：过契约禁词 **且** 过此人审（或按上节如实标注 AI 预检-only），才能进可见池 / overlay。  
3. **现在 PO 未点名英语审核人** → B 类句稿 PR **不得** 声称 en 扩库完成；可先写稿进仓库跑 CI，不上线 overlay。

### 4.2 日语闸

1. **点名** 能审日语语气的人；书面同意审本刀四通道日语句。  
2. 每条日语句：过禁词 **且** 过此人审，才能进可见池 / overlay。  
3. **现在 PO 未点名日语审核人** → 本刀 **只扩英语**（与 en 线 **并行**，不必等日语）；日语 **维持现网冻结表规模**。不得用机器翻译顶人审。

若点名后产能不够：日语可按子类型 **4–6** 条（仍须人审），不要为凑 8 条放宽语气。PO 倾向：**别为省事放弃日语**——对外声称 en+ja，每子类型 4–6 条总量约二十来句，请日语母语者付费审一次，成本通常小于让用户长期只听 1–3 句。一时找不到人 → 仍按默认只扩英语。

### 4.3 我认为最合理的（本回合默认）

**英语、日语各须点名才写「人审完成」**；未点名前只扩英语句稿 + 仓库 CI，日语不动。中文继续草稿、不可见。

口令「日语也扩到 8–12」在未点名日语审核人时 **不执行**。

## 5. 检查器与红线样本

新句不是写进仓库就完。须同时进现成检查器，避免以后改禁词表时误伤近邻观察句。

### 5.1 新句必过（仓库 CI）

1. `npm run check:companion-contract`（与 `docs:check` 同一张契约禁词表）——**只扫仓库里登记的文件**。  
2. 邀请切片仍过现网窄正则 `AWAKEN_FORBIDDEN_COPY`（不替代契约全表）。  
3. **人审**（英语 §4.1 点名；日语 §4.2 点名；或如实标注 AI 预检-only）。字面过关 ≠ 语气过关。

### 5.1.1 Overlay 不能绕过 CI（强制）

云端下发的句子 **若只存在于 Worker / D1**，仓库 `check:companion-contract` **扫不到**，等于绕开契约——而 overlay 的价值正是改句不必发版，**更须** 双闸：

| 闸 | 锁 |
|---|---|
| **部署前** | Overlay 句子的 **源文件必须在仓库**（例如 `focus-tiger/` 下 content 或 cloud 侧与 repo 同步的 JSON/md；B 类 Brief 锁路径）。**Redeploy / 部署前** 对源文件跑 **同一张** 禁词表（`check:companion-contract` 或与之共表的 `matchForbiddenPatterns`）。禁止只在控制台改 D1 而不进 repo |
| **展示前（客户端）** | 解析 overlay 后、**用户可见之前**，对 **最终展示字符串**（含填槽后）再调 [`matchForbiddenPatterns`](../../scripts/companion-contract-forbidden.js)（与 CI 同表）。非空 → **丢弃该句，回退冻结表**。不用模型，成本可忽略 |

B 类实现 Brief **必须** 含：源文件路径、部署前扫描命令、客户端复扫挂点（与填槽流水线 §5.2 衔接）。

### 5.2 槽位最终串

`{minutes}` 等槽 **只由代码填**，禁止模型填。流水线：

```
人审通过的模板
  → 模板过禁词表
开口
  → 代码填槽
  → 填完的最终字符串再跑同一张禁词表
  → 不过则回退该通道冻结表锚句
```

结束低语须准备至少一组填槽后的最终串样例（例如 1 / 25 / 90 分钟）进检查或单测，防止只扫带花括号的模板。

### 5.3 近邻放行样本（建议本刀实现 Brief 必带）

在 [`companion-contract-samples.js`](../../scripts/companion-contract-samples.js) **增加若干 `expect=allow` 近邻**，取自本刀新句方向（不是把整库复制进样本集）：

| 方向 | 为何 |
|---|---|
| 观察分钟（填槽后） | 练习事实，防 C-02 误伤 |
| 离开后再聚焦的观察句 | 观察离座，防 C-01 / C-04 误伤 |
| 可拒绝的邀请短句 | 防 C-08 被写成催促后，检查器仍放行合法邀请 |

条数建议 **3–5** 条 allow，维持坏样本 / 放行样本两比率各 **1.0**。**不** 把危机句塞进本集。日文真正口语样本仍须人审后另做；未扩日语时不假装日文样本已覆盖。

通过检查 **不等于** 陪伴已验证，也 **不等于** 阶段 1。
