## 0. 大白话

对比已经点头：这四条陪伴短句先不要在本机现编，先把每条路上的固定句子加一点、审完再发出去。本页只写怎么加、加几句、谁审日语、怎么过检查、怎么下发。屏幕上的句子现在还是原来那几句。本页通过 **不等于** 可以开始写新台词，也 **不等于** 可以开阶段 1。

## 3. 不重复取用

线上还没有真实用户；新鲜感用小库 + 取用规则先挡住，不靠堆句子。

| 项 | 锁 |
|---|---|
| 粒度 | **同一用户 · 同一通道 · 同一正式语言** |
| 规则 | 连续 **N** 次开口 **不得** 再抽到刚抽过的那几句 |
| **N** | `min(7, 该通道该语言可见条数 − 1)`。8 条 → 连续 7 次不重复；12 条 → 连续 7 次不重复 |
| 池空 / 条数 &lt; 2 | 退回现网冻结表那一句；不得为凑 N 现场生成 |
| 槽位句 | 去重按 **模板 id**，不按填完 `{minutes}` 后的最终串（否则「坐了 12 分钟」和「坐了 13 分钟」会被当成两句而实际是同一骨架） |
| 存储 | 只记模板 id 环（可本机）；**禁止** 记生成原文或倾诉原文 |
| 实现落点 | 将来 B 类 Brief 指定；本页不改 `src/`。可对照现网日签 `recentIds` 精神，**不得** 和日签 / Quiet Line 混用同一把锁 |

将来若真有「句子重复让人腻」的用户反馈，再开第二刀扩库，不在本刀预支。

## 4. 日语审核人

产品对外只声称 **英语和日语**。人审是 R 相对本机池化的核心优势；审核人必须能判断 **日语语气**（观照、不催、不诊断），不是只会对照英文字面。

### 4.1 闸（缺一则日语不扩）

1. 说明书或实现 Brief 里 **点名** 一位能审日语语气的人（PO 本人、指定母语/近母语审稿人、或书面委托的编辑）。  
2. 该人书面同意审本刀四通道日语句。  
3. 每条日语句过契约禁词 **且** 过此人审，才能进可见池 / overlay。

**现在没有点名** → 本刀 **只扩英语** 到 8–12；日语 **维持现网冻结表规模**，不新写日语变体。不得用机器翻译顶人审。

若点名后审稿产能不够：日语可缩到每通道 **4–6** 条（仍须人审），不要为凑 8 条而放宽语气。

### 4.2 我认为最合理的（本回合默认）

**英语扩到 8–12；日语维持现状，直到 PO 在本页或实现 Brief 点名审核人。** 原因：没有可靠日语审稿人时，扩日语会把「人审优势」做空，对外声称也会空。中文继续草稿、不可见。

口令「日语也扩到 8–12」在未点名审核人时 **不执行**。

## 5. 检查器与红线样本

新句不是写进仓库就完。须同时进现成检查器，避免以后改禁词表时误伤近邻观察句。

### 5.1 新句必过

1. `npm run check:companion-contract`（与 `docs:check` 同一张契约禁词表）。  
2. 邀请切片仍过现网窄正则 `AWAKEN_FORBIDDEN_COPY`（不替代契约全表）。  
3. **人审**（英语：能判断观察语气的审稿；日语：§4 点名的人）。字面过关 ≠ 语气过关。

### 5.2 槽位最终串

`{minutes}` 等槽 **只由代码填**，禁止模型填。流水线：

```
人审通过的模板
  → 模板过禁词表
开口
  → 代码填槽
  → 填完的最终字符串再跑同一张禁词表
  → 不过则回退该通道冻结表锚句
```

结束低语须准备至少一组填槽后的最终串样例（例如 1 / 25 / 90 分钟）进检查或单测，防止只扫带花括号的模板。

### 5.3 近邻放行样本（建议本刀实现 Brief 必带）

在 [`companion-contract-samples.js`](../../scripts/companion-contract-samples.js) **增加若干 `expect=allow` 近邻**，取自本刀新句方向（不是把整库复制进样本集）：

| 方向 | 为何 |
|---|---|
| 观察分钟（填槽后） | 练习事实，防 C-02 误伤 |
| 离开后再聚焦的观察句 | 观察离座，防 C-01 / C-04 误伤 |
| 可拒绝的邀请短句 | 防 C-08 被写成催促后，检查器仍放行合法邀请 |

条数建议 **3–5** 条 allow，维持坏样本 / 放行样本两比率各 **1.0**。**不** 把危机句塞进本集。日文真正口语样本仍须人审后另做；未扩日语时不假装日文样本已覆盖。

通过检查 **不等于** 陪伴已验证，也 **不等于** 阶段 1。

## 6. 下发：沿用句包 overlay

扩库句子进 **云端 overlay**，本机 **冻结表兜底**。这与 [`ANTI_PLAGIARISM_LAYER.md`](../ANTI_PLAGIARISM_LAYER.md) 一致：难抄的是云上句正文；没网仍有冻表。额外好处：句子比写死在客户端包里更难整表抄走。

| 项 | 锁 |
|---|---|
| 管道 | 既有品味层预取槽（或与四通道对齐的独立字段）。**禁止** 开口当拍拉网 |
| 冻表 | 现网 1–3 句锚句留在客户端；overlay 失败 / 没网 / 开关关掉 = 冻表 |
| 未知 schema | **直接丢弃** overlay，干净用冻表。升 `schemaVersion` 须同步冻表形 |
| 非法 key / 空包 | 丢 overlay，不半套合并 |
| PR 边界 | **扩库 overlay 单独 PR**。禁止与 Quiet Line / Confide 句库 / Calm Action / YPE Pack / 付款路径混在同一个 PR |
| 生产 | 源码合入 ≠ 现网。Worker Redeploy 须口令「部署」 |
| 杀开关 | `?tasteLayer=0` 或等价开关关掉后行为 = 现网冻表 |

后台网络三问（将来 B 类运行时 Brief 必答，本页只锁口径）：时机并进已错峰预取；JSON 相同不另写盘；慢网不得挡 Sit / 开口。
