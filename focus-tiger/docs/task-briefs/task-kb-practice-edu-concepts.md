## 0. 大白话（给拍板用）

用户问「接地练习是什么」「正念大概是什么意思」时，阿寅可以给一段**读完就完整**的概念说明：这是什么、为什么常被认为有帮助。  
用户问「现在带我做一遍」「我很慌，一步步教我」时，阿寅**不准**自己写第二套练习脚本——菜单里已经有接地 / 呼吸入口，只许指路，不许代读、不许新编步骤。  
这条线用公开的监管和学界标准钉死，**不需要**再请一位心理专业人士来校准「科普 vs 引导」。产品 / 内容团队按第一节那张表逐项核对即可。

## 一、范围线：哪些能做，哪些不能做

这条线不是本任务书自己发明的，而是三条已经在监管和学界公开使用的判定标准的合并结果。生成或审核出现疑义，先回来对照；**信源再权威，也不许把禁止列改成允许列。**

### 1.1 编辑口诀（先于细表）

**答案读完，用户要不要接着做动作？**

- 不要 → 才可能是科普概念类（仍须过下面三张表）
- 要（吸气、数数、把脚放平、闭眼跟做、跟我念下一步）→ **一律不做**

「带着做一遍」就是具体引导，也就是急救型草稿池想挡住的东西。权威网页、综述、公共卫生材料都不能让这条口诀松动。

### 1.2 标准来源（可公开核对，不另请人把关）

1. **FDA「意图指向」——通用健康 vs 治疗性软件**  
   判断核心不是内容严不严肃，而是这段话有没有指向**诊断、治疗、缓解或预防某个可诊断的疾病 / 病症**。正念、放松、日常压力这类泛泛健康陈述，只要不对某个心理疾病提出治疗主张，通常落在通用健康；针对焦虑的认知行为疗法、针对创伤的暴露疗法则是治疗性干预。  
   FDA 还把通用健康表述再分一档：只说「促进放松、管理压力」风险低；一旦写成「可能有助于降低某某病风险 / 缓解某某症」风险陡增。  
   **写进禁止清单**：正文和适用场景都**不能出现具体疾病 / 症状名称**（焦虑症、惊恐发作、创伤后应激障碍等），哪怕只是「适用人群」。

2. **AI 个性化程度——通用讲解 vs 针对「你」的建议**  
   阿寅是对话式的，最容易在这一层越界。针对个人的风险判断、和下一步健康行动挂钩的指令（「你现在这种情况应该……」「建议你立刻做正念」）更接近临床指导，而不是生活方式说明。更稳的定位是「支持、认知、追踪」，不是「解读、预测、指导行动」。  
   **写进操作规则**：可以说「正念练习通常被认为对情绪调节有帮助」（普遍认知）；**不能**说「你现在这种情况，应该做正念」。

3. **心理教育（psychoeducation）——被动信息 vs 主动引导**  
   被动心理教育是读传单、邮件、说明页：读完即完整，参与度低。主动引导是有人（或系统）带着做一遍结构化练习。本库只做前者。

### 1.3 合并判定表（三项必须全落在允许列）

| 维度 | 科普概念类（可做） | 具体引导类（不做） |
|---|---|---|
| 是否绑定具体病症 / 症状 | 否——只讲通用健康概念 | 是——「焦虑发作时」「创伤后」「惊恐时」等 |
| 是否针对「你」给行动指令 | 否——讲普遍原理 | 是——「你现在应该……」 |
| 交付形式 | 被动阅读——一段说明，读完即完整 | 主动引导——带着做一遍 |

三项全部在「允许」列，才能进入起草。任意一项在「禁止」列 → 本 Brief 不覆盖，维持 `KB-PSY-DRAFT-*`：`yin_may_retrieve: 否`。

### 1.4 举例对照

| 允许生成 | 禁止生成 |
|---|---|
| 「正念是什么」 | 「教我做一次正念练习」 |
| 「为什么接地练习常被认为有帮助」（原理，不讲步骤） | 「现在很慌，一步步带我做接地」 |
| 「专注练习和冥想有什么区别」（概念辨析） | 任何呼吸节奏、计数、身体动作的具体指令 |
| 指向产品里已有的接地 / 呼吸入口（复用已有指路条，如 `KB-FUNC-0002` / `0006`） | 重写或改写 `RESET_GROUND_*` / `RESET_LOOK_*` / `RESET_BREATH_*` 引导语正文 |

科普答错的后果是「概念不准确」。引导答错的后果可能是「在情绪脆弱的当下给出不合适的操作」。后者正是「急救型没有固定审核人，先不进阿寅」要挡住的；本 Brief 不重新打开这个口子。网上材料再权威，也不能代替这条产品边界。

## 二、为何不能套用「寅币 / 备份」那条流水线

`task-kb-scaled-production.md` 能「盘点不新造」，前提是答案是产品自己的既定事实（按钮在哪、备份存什么）。权威源是 locale / 规则源码；出错形态是「指错路」。

本批内容若写成「辅导」，权威源会变成网上的练习脚本，出错形态是「教错做法」。所以：

| | 功能短答（已有流水线） | 本 Brief（科普概念） |
|---|---|---|
| 权威源 | `src/locales` + 规则源码 | 公共卫生 / 学术科普材料（只作参考，必须重写） |
| 用户读完要做什么 | 去点已经存在的按钮 | **什么动作都不必做**；若要练习，只许指到现网入口 |
| 人审 | 抽查语气、禁编步骤 | 对照第一节表 + 禁止事项核查；仍不需要心理咨询资质 |
| 与急救型草稿池 | 禁止念 `RESET_*` | **同一条硬闸**，不因换了「从网上找的」包装而松开 |

两套流水线分批生产、分批审核，禁止混进同一份 PR。

## 三、信源规则：权威，但不能照搬

### 允许参考

- 公共卫生机构面向公众的科普页（政府卫生部门、大学医学中心）
- 同行评审**综述**里已被广泛转述的概念结论（不摘原始数据表）
- 高校心理系 / 精神卫生中心面向公众的说明

### 禁止当原料

- 商业冥想 App 营销页（疗效夸大、推销）
- 未标注来源的社交 / 自媒体
- 任何暗示「治疗 / 治愈 / 预防」特定疾病的材料

### 改写（版权与准确性并重）

- 正文必须**完全重新组织**；禁止整段摘抄，也禁止近义词替换、句式不动的轻度改写
- 每条记录 `信源类型`（知道大致来自哪类材料即可，不必逐句脚注）
- 不写具体数字或疗效百分比（易过期、像疗效主张）
- 对外可念短答以 **en** 为准；ja 可后补；zh 只作内部草稿槽，不得假装已是 v1 产品语言（与主库一致）

## 四、字段结构（主模板 + 本类目新增）

复用 `product-knowledge-base.md` 标准字段。本类目额外：

| 字段名 | 说明 |
|---|---|
| `id` | `KB-EDU-NNNN`（与 `KB-FUNC-*` / `KB-PSY-DRAFT-*` 分号段） |
| `一级分类` | `心理练习` |
| `二级分类` | `科普概念` |
| `内容类型` | 固定 `科普概念` |
| `信源类型` | 第二节允许清单中的一类 |
| `禁止事项核查` | 见下表；任一项为「是」→ 不得送审 |
| `审核人角色` | **不要求**心理咨询资质；产品 / 内容团队；须写到人 |

`yin_may_retrieve` 仍须人审「已通过」后才可置「是」。未通过 = 否。

### 禁止事项核查（起草自查 + 审核复检）

| 项 | 必须为「否」 |
|---|---|
| 具体步骤 / 动作指令 | 读完不用跟着做 |
| 治疗 / 诊断 / 治愈 / 预防类表述 | 与 wellness 免责一致 |
| 具体数字 / 疗效百分比 | 不写 |
| 具体疾病 / 症状名称 | 含「适用场景 / 适用人群」 |
| 针对「你」的个性化行动指令 | 不写「你现在应该」 |
| 整段或轻度改写照搬信源 | 必须重写 |

## 五、生产流程（点头后分刀，一次一刀）

1. **候选主题**：AI 可先提「正念 / 专注 / 接地领域常见概念问」清单，**PO 筛选**后才起草正文。候选清单不是短答，不过第一节红线，风险低。  
2. **AI 起草**：按第三节信源规则写待审 YAML；填禁止事项核查；短答 en；需要练习时只指到现网入口 / 已有 `KB-FUNC-*`，不复述引导语。  
3. **人审**：对照第一节口诀 + 判定表 + 禁止事项核查。不要求心理咨询资质。越界 → 驳回，改指路或丢回急救型草稿池。  
4. **入库**：独立小 PR。通过后入「陪伴可检索」，`内容类型: 科普概念`。禁止与功能短答扩批、寅币 / 备份批混提。  
5. **catalog**：仅「已通过」条目进 `productKnowledgeCatalog.json`。此步为 **B 类**，须另发口令。

本 Brief 点头 ≠ 允许把示例 YAML 直接标已通过。

## 六、冲突扫描（文档方向锁 · 无运行时）

对照 `SCENARIO_TESTS.md` 场景 AE（产品问）与急救型草稿池：

| 轴 | 相邻 | 结论 |
|---|---|---|
| 强度 | 场景 AE 产品问；接地 / 呼吸练习本体在菜单 | 本批只增产「读完即完整」的概念句，不加重倾诉里的练习步骤，不抢时长事实路由 |
| 人设 | 阿寅是观照者，不是教练 / 客服手册 | 禁止「你现在应该做 X」；命中后仍原样短答，不续写引导 |
| 职责 | `KB-FUNC-0002` / `0004` / `0006` 指路或术语；`KB-PSY-DRAFT-*` 管引导语正文 | 「是什么」走 `KB-EDU-*`；「在哪做」走已有 FUNC；「带我做」继续只指路、不念脚本。禁止 EDU 条把 FUNC 入口说明扩成第二套步骤 |

**无冲突**，前提是第一节口诀不被「权威信源」松开。实现 catalog 写入前若改可检索集合，再扫一次 AE。
