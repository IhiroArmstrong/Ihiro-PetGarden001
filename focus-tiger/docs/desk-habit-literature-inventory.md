## 0. 结论（先看这六句）

1. **人机共修的目标（双向适应、闭环随时间更协同）已经写在口径里。** 现网已经有「一起坐、不催、按这个人变安静」；**缺的是用真人对照证明闭环有效**，那一行仍是 **T54** 90 天实验（搁置 · 未排期），不要另开一条研究任务。
2. **小型互惠已经用「原谅、不愧疚」在做，不是用「宠物向你索取照料」。** FocusBuddy 的水瓶宠物互惠，和我们「正念伙伴、禁止喂养/健康退化/照料责任」是两条路。抄宠物索取 = 回退成电子宠物。
3. **Yin 不反映「数字健康状态」。** 练习观察纸只看练习节奏，禁止健康分 / 红黄绿。把阿寅做成数字健康仪表盘，要先推翻 [`PRACTICE_PAPER.md`](./PRACTICE_PAPER.md)；那是 **T28** 已搁置的拦路虎。
4. **环境光日程灯不要做。** 现网已有专注金环、夜间略降亮度、到点应用内横幅、电脑版系统通知。再加一盏常亮日程灯，正好踩上平静技术「用户根本没注意到」的风险，也容易变成第二套催促。
5. **定时问早餐、因长期不吃而善意提示：不做。** 作息盘点已写「饮食、体重、用药、情绪低落监测 = 不做」（C-01 / C-06）。Yin 判断「你没吃早餐」= 睡眠教练那条路的翻版。
6. **唯一值得排队、且形状已有先例的补缺：用户自己设「开始伏案时坐一下」**（**T70**，搁置 · 可选，Brief 待点头）。形状抄 **T61** 收工钟：只陪用户自己的目标，不替用户定义好习惯。

## 2. 桌面工作习惯：现网已陪什么 / 合适再陪什么

### 已经合适、不要重复造

| 习惯 | 现网 | 不要改成 |
|---|---|---|
| 伏案久了伸展 | 活跃累计约 2 小时舒展邀请（共享日额度） | 不要加健康分 |
| 注意力离开再回来 | Re-focus 观察句；不说「你又走神了」 | 不要加愧疚账 |
| 下班边界 | Work Transition 仪式（用户自己点）；**T61** 用户自设收工到点轻问 | 不要 Yin 看出熬夜 |
| 每天来坐 | 用户自设每日时分提醒；今日练完不出 | 不要强迫打卡 |
| 要不要停一下 | **T51** 邀请，可拒绝；**T52** 结束三态 | 不要自动开练习 |
| 练习是否过量 | 单日软封顶 | 不要新催促 |

### 合适、尚未做（仅 T70）

| 习惯 | 为何合适 | 形状 | 本槽位 |
|---|---|---|---|
| **开始伏案时先坐一下**（用户自己设钟，例如上午坐下办公的时刻） | 与 FocusBuddy「桌面工作习惯」同场景，但走 **T61** 已验收的「只陪你说过的目标」 | 新键存时分；到点轻问；可拒绝；受 **T58** 暂停；专注中让位；**不问吃了什么** | **T70** 搁置 · 可选 · Brief 待点头 |

### 不合适（保持不做）

饮食与早餐质量、体重、用药、情绪低落监测、日历环境灯、宠物饥饿/要水、数字健康红黄绿、Yin 判断「你长期不吃早餐所以开口」。

## 3. 「做得足够吗」与提升建议

**对品牌定位：足够，且不应按电子宠物补齐。** 正念伙伴已经覆盖互惠里「不索取、易原谅」的一半；另一半「一起练」已有运行时。

**对研究空白：不够，但这是评测不够，不是功能清单不够。** 综述指出的「闭环是否随时间提升协同」= **T54** 核心假设。再加早餐灯或健康仪表盘，反而让实验更脏。

**我认为最合理的后续（只这一条新产品）：** 先点头 **T70** Brief（开桌锚点，T61 同形），再写代码。其余文献项登记为不做或并入已有 T 号。**T68** 纪念画仍按原四闸走，不因本盘点插队。

较弱方案：立刻做早餐问询或环境灯——与红线冲突，且平静技术自己警告会漏看。仅在用户书面推翻作息盘点 §4 与练习纸方向锁时才重议。
