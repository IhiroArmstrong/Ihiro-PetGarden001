## 2. 固定词条（禁止换字）

| 词条 | 含义 | 禁止当作同义词乱用 |
|---|---|---|
| **槽位 P1 / P2** | 当前在排、有明确分支或 PR 的工作 | 「#1 #2」「第一刀」「下一刀」（未写 P 编号时） |
| **未排期** | PO 明确不安排；无分支、无 PR、无开工口令 | 单独写「高风险全放下」（易让人以为整队取消） |
| **纯文档 PR** | 不改 `src/` 运行时；`docs:check` 类验证 | 「文档刀」「账本 PR」（不说清是否动代码时） |
| **产品旁支** | 改用户路径或发送链等运行时 | 「功能 PR」「实现刀」 |
| **口令** | 用户一句话触发 Agent **开始执行**已排槽位（不是新任务名） | 把口令写成「又冒出来的一条安排」 |
| **rebase develop** | 旁支合入前对齐 `origin/develop` tip | 「对齐最新」「跟一下 develop」（不说动作时） |

## 3. 三种「风险」——不得混为一谈

| 类型 | SSOT | 指什么 | 本队列里谁命中 |
|---|---|---|---|
| **高风险面** | `DEV_WORKFLOW_QUALITY.md` §2.3 | 付款、Confide 发送、z-index 叠层等触及须复检的**产品面** | P2（Confide）触及时须走日常回归锁；**不等于**「整项未排期」 |
| **Playbook 中高风险** | `RISK_MITIGATION_PLAYBOOK.md` §1 | 多模块穿透、新状态进生产路径 | P2 若切片大可能套用；P1 通常不必 |
| **根因行动暂缓（PO 标签）** | `ISSUE_LEDGER.md` · `root-cause-hardening.md` | A15–A17 刻意不做；账本写「未排期」 | **仅 A15 · A16 · A17** |

汇报时：**写清是哪一种**。禁止用「高风险」一句概括 P2 与 A15–A17。

### A15 · A16 · A17 是否「高风险」？

| 编号 | 内容 | PO 暂缓理由（账本） | 与 §2.3「高风险面」关系 |
|---|---|---|---|
| **A15** | 艺术品入库脚本默认模式 + R2 上传前确认 | **操作/资产破坏风险高**（曾抠坏上传） | 非 §2.3 表内条目，但是**真高风险作业** |
| **A16** | 5173 版本角标 + 合入后 sync QA | 流程刀；降低「旧代码」误会 | **低**产品面风险 |
| **A17** | PR 跨模块范围 CI 提醒 | 流程刀 | **低**产品面风险 |

**标准说法**：A15–A17 状态叫 **「未排期（根因行动 A15–A17）」**；其中 A15 可补充 **「资产入库高风险」**；**不要**说「高风险全放下」而不列编号（以免误伤 P2）。

## 4. Agent 汇报检查（强制）

向 PO 列安排时须：

1. 用 **P1 / P2 / 未排期 / 可选** 之一标每项。  
2. 同一安排只保留 **一行**；改顺序时写「更新队列」并给整张表，不追加矛盾段落。  
3. 出现 PR 编号时同时写 **槽位名**（例：P1 · PR #1288）。  
4. 不写未在 §1 或 PO 当次消息里出现的 **新槽位**；新工作只登记 `TASKS.md` / `task-entries/`，等 PO 排进槽位。  
5. 「可同时审 / 须先 rebase」分开写清，不合成一句「顺序无所谓」。
