# Quick Start（空格键极速开始）— 功能 PRD

## 1. 背景与目标

面向"熟练用户 / 赶时间开工"的场景（对标角色 Kelly）：用户不想每次都走完整的 Arrival Practice（Notice → Choose → 调频），希望在空闲首页按一下 `Space` 键，直接用上一次的会话配置（时长 + 模式）极速开始专注。

**目标体验**：打开 App → 看一眼呼吸光晕 → 按 Space → 开始。全程 ≤ 1.5 秒，零鼠标点击。

**非目标（本期不做）**：
- 快捷键自定义（改成其他按键）
- 多设备间"上次配置"云同步
- 根据时间段/场景智能推荐配置（而非单纯"记住上次"）

---

## 2. 核心原则（必须遵守）

1. **禁止重新实现"开始专注"逻辑**：本功能只是换了一个触发入口，最终必须调用现有的开始专注函数（例如 `startFocusSession(config)`），不允许新写一套开始流程。
2. **模块解耦**：键盘监听模块不直接调用业务逻辑，而是 dispatch 一个自定义事件，由外部决定如何响应。
3. **默认关闭 / 白名单开启**：快捷键监听默认不生效，只在明确列出的页面状态下才激活（见第 5 节），而不是"除了某些情况都生效"的黑名单思路。

---

## 3. 模块拆分与目录结构

```
src/features/quick-start/
  last-session-store.js    // 记住/读取上次会话配置
  keyboard-shortcut.js      // 全局键盘监听 + 状态判断 + 防抖
  hint-visibility.js        // 首次引导 / 常驻提示的展示逻辑
  QuickStartHint.jsx        // 底部提示 UI 组件
```

---

## 4. 任务拆解

### 任务 1：记住上次会话配置（`last-session-store.js`）

- 每次用户手动选择时长/模式后，写入 `localStorage`：
  ```js
  {
    duration: number,      // 分钟
    mode: string,          // 例如 'here-and-now'
    timestamp: number      // 写入时的时间戳
  }
  ```
- 提供 `getLastSession()`：
  - 若无记录，返回默认值 `{ duration: 25, mode: 'here-and-now' }`
  - 若有记录，直接返回
- 提供 `saveLastSession(config)`，在用户每次手动选择配置的地方调用

**验收标准**：
- [ ] 刷新页面后配置仍保留
- [ ] 从未设置过的新用户拿到合理默认值，不报错

---

### 任务 2：全局键盘监听（`keyboard-shortcut.js`）

监听 `document` 的 `keydown`：

- 命中 `Space` 且满足以下**全部**条件时才响应：
  1. 当前路由/页面处于"空闲首页"白名单状态（见第 5 节），非白名单一律忽略
  2. `document.activeElement` 不是 `input` / `textarea` / `[contenteditable]`
  3. 距离上一次成功触发 ≥ 500ms（防抖，防止手滑连续触发）
- 命中后：
  - `event.preventDefault()`（阻止浏览器默认的页面滚动行为）
  - `dispatch` 自定义事件 `quick-start-requested`，不直接调用开始逻辑

**验收标准**：
- [ ] 输入框聚焦时按 Space 不触发，且能正常打空格字符
- [ ] 计时进行中 / 设置弹窗打开 / 引导流程中按 Space 不触发
- [ ] 非空闲首页（如设置页）按 Space 不触发，也不影响该页面原本的滚动行为
- [ ] 快速连按两次 Space，只触发一次
- [ ] 按 Space 时页面不会意外滚动

---

### 任务 3：事件响应 + 与 Arrival Practice 的分支（业务层，非 quick-start 模块内）

```js
// 监听 quick-start-requested 事件后：
document.addEventListener('quick-start-requested', () => {
  const config = getLastSession();
  startFocusSession(config); // 调用现有的开始专注函数，不要重新实现
});
```

- Space 快捷启动 = **完全跳过** Arrival Practice（Notice → Choose → 调频）
- 常规点击"开始"按钮 = 保留完整 Arrival 流程，服务新手/需要仪式感的用户
- 两条路径共用同一个底层 `startFocusSession()`，只是前置步骤不同

**验收标准**：
- [ ] Space 触发后直接进入计时，无中间弹窗/动画阻断
- [ ] 手动点击开始按钮的流程不受影响，Arrival 照常展示

---

### 任务 4：误触保护（新增，原方案未覆盖）

- Session 开始后的**前 3 秒**内，保留一个明显的取消方式：
  - 建议：再次按 `Space` = 立即暂停/取消本次 session（而不是当作"开始第二次"）
  - UI 上可短暂显示一行"按 Space 可撤销"提示，3 秒后消失
- 这个逻辑属于"开始后的短暂窗口期状态"，建议在 `startFocusSession` 调用方就近处理，不下沉到 `keyboard-shortcut.js` 模块里，保持模块职责单一

**验收标准**：
- [ ] 误触发后 3 秒内可一键撤销，且撤销后状态干净（不留计时残留）
- [ ] 超过 3 秒后再按 Space 不再触发撤销（避免和"计时中按 Space"的正常逻辑冲突）

---

### 任务 5：底部提示 UI + 首次引导（`QuickStartHint.jsx` + `hint-visibility.js`）

两种展示状态，用独立的 localStorage flag 管理（`hasSeenQuickStartHint`，与"上次配置"分开存储，避免逻辑耦合）：

1. **首次发现**（用户第一次拥有"上次会话记录"，且从未见过提示）：
   - 用稍明显的一次性引导（toast / 轻微高亮）介绍这个快捷键
   - 展示后写入 `hasSeenQuickStartHint = true`，之后不再用这种强提示
2. **常驻态**（已见过引导 / 或本身就是老用户）：
   - 底部一行小字："按 `Space` 极速开始（25 分钟 · Here & Now）"，动态展示当前的上次配置
   - 若从未有历史记录：不展示该提示，或展示引导语"选择一个任务开始"

**验收标准**：
- [ ] 首次引导只出现一次，刷新/重进不会重复弹出
- [ ] 常驻提示的文案随"上次配置"变化而更新

---

## 5. 快捷键生效范围（白名单）

**只在以下状态下监听生效**：
- 空闲首页（Idle 首页），且未打开任何弹窗/模态框

**其余所有状态一律不生效**，包括但不限于：
- 计时进行中
- 设置页 / 设置弹窗
- 引导流程（onboarding）
- 评分/反馈弹窗
- 任何 modal 打开状态

> 采用白名单而非黑名单的原因：后续新增页面或弹窗时，默认不会被 Space 意外打断，不需要每次新增页面都记得去黑名单里补一条。

---

## 6. 音频自动播放兼容处理

浏览器会拦截"未经用户交互"的音频自动播放，需要降级策略：

- 若用户本次会话中已发生过至少一次交互（点击、按键等），Space 触发时正常播放背景音乐淡入
- 若确实是全新页面加载、从未有过任何交互（理论上较少见，因为按 Space 本身就是一次交互，通常可以正常播放）：不要让音频播放失败阻塞开始流程，音频报错应被静默捕获，视觉呼吸光晕正常展示，专注计时正常开始

**验收标准**：
- [ ] Chrome / Safari 下按 Space 开始流程不因音频报错而中断或报错到控制台阻塞渲染

---

## 7. 建议开发顺序

1. 任务 1（记住配置）—— 独立可测，和键盘无关
2. 任务 2（键盘监听 + 白名单 + 防抖）—— 重点测边界情况（输入框、非白名单页面、连按）
3. 任务 3（事件响应 + 分支逻辑）—— 接入现有开始函数
4. 任务 5（提示 UI）—— 纯展示层，风险最低，可与任务 2/3 并行
5. 任务 4（误触撤销）—— 建议放最后，依赖任务 3 跑通之后再加

---

## 8. Out of Scope（明确不做，避免 Cursor 过度发挥）

- 不做快捷键自定义
- 不做多设备同步
- 不做"根据时间段智能推荐配置"这类智能化逻辑
- 不新建一套独立的"开始专注"实现
