## 1. 结论

本轮补齐了六次隐私同意操作、首次使用到倾诉的可复述步骤、桌面宽窗 C01–C15 逐条按钮发送、10-02 二十四条逐条窗口发送，以及向量就绪 / 不可用两配置对照。

仍有两项硬事实：

1. **向量就绪时仍漏 C04、C11。** 两条都在真实宽窗进入 `generate`。
2. **窄窗 Share 按钮不能真实点击。** 390 px 下首页底部导航拦截按钮指针事件；本轮只能改用产品已有的 Enter 发送路径完成路由采集。因此“窗口内逐条点发”在窄窗仍未闭合。

另需澄清：#1627 打开的 T14 是**倾诉卡内求助资源入口**，不是把倾诉产品入口对所有用户默认开放。当前第一次使用到倾诉仍须 `?confide=1` QA 入口；不能写成第一份安装包用户自然可达倾诉。

## 3. 真实首次使用到倾诉

本轮使用独立用户目录，从首次打开开始走可见控件；未调用 `skipToBegin`，未强制点击。

1. 打开 fresh app。
2. 首次目标卡出现。
3. 点 **Mindfulness & meditation**。
4. 进入 Focusing。
5. 点 **Rise**，Reflection 出现。
6. 点 **Skip all → Continue**，回到 Idle。
7. 点可见耳朵入口，打开倾诉卡。
8. 首次 Yin Memory 同意层点拒绝，随后输入可发送。

边界：第 7 步依赖 `?confide=1` QA 参数；当前产品 mount 仍为 off。以上证明 QA 窗口链可走，不证明安装包默认入口自然可达。

## 4. 六次隐私同意操作

从可见 `?` → Purpose → Privacy 进入隐私页。三组开关各开、各关一次，六次最终状态均与操作一致；R2L-01 不再复现。

| 操作 | 最终状态 | 同操作时间窗内的主进程请求 | 判读 |
|---|---|---|---|
| YPE 个性化开 | on | `POST /api/lantern-presence` | presence 为周期请求，不能归因于 YPE；本轮无可上传 YPE 数据 |
| YPE 个性化关 | off | `POST /api/ype-personalization-delete` | 关闭后删除路径真实发出 |
| 付费漏斗开 | on | `POST /api/monetization-funnel-ingest` | 只在明确同意后发出 |
| 付费漏斗关 | off | 无 | 未见关闭后继续 ingest |
| T54 研究开 | on | 无 | 开关本身不立即上传 |
| T54 研究关 | off | `POST /api/lantern-presence` | presence 为周期请求；未见 T54 上传 |

补充抓取：

- Chromium net-log：向量两配置各 50,440 bytes；未开敏感捕获模式。
- 主进程 `fetch` 运行时记录到精确 host + path；调用仍委托给真实 `fetch`。
- 每次开关后另取主进程 `lsof -nP -a -p <pid> -iTCP`。
- 启动 / 练习期间存在远程配置与 presence 请求；未见 YPE ingest、付费漏斗 ingest、T54 上传在其同意之前发出。

因此 V1 的“开关入口能否逐一开关”已由未检变为**已检**；本补跑只补最小运行证据，不替代完整隐私审计。

## 9. 对第一份安装包门槛第 3 条的判读

门槛第 3 条要求 R2-lite 包含窗口点发送以及有 / 无向量两配置。

- 有 / 无向量：**已补齐**。
- 宽窗逐条按钮发送：**已补齐**。
- 真实首次使用链：**已补齐到 QA 倾诉入口**；安装包默认用户自然可达仍不成立。
- 窄窗逐条按钮发送：**未补齐**，因为真实按钮被底部导航挡住；Enter 只完成路由证据，不能冒充点击证据。

因此该门槛应记为：**证据已大幅补齐，但仍有窄窗点击阻断，暂不无保留勾选。**
