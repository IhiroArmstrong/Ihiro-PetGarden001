# Task Brief B2 — 测试、发布与项目管理审计

- 所属基准：`AUDIT_BASELINE.md` v1.0
- 负责维度：③ 测试与发布（10%）、④ 项目管理（8%）
- 建议执行方式：独立新会话，一个会话只做本 Brief
- 输出目录：`docs/audit/findings/<日期>/`

## 1. 目标

评估测试体系能否拦住真实回归，发布与回滚是否可靠，项目管理（Epic / Issue / PR / 搁置登记）是否让工作可追溯、可度量。

## 2. 范围

**纳入：**
- 单测 / 集成 / e2e / 场景测试（含 SCENARIO_TESTS 与 Local AI 场景映射）、CI 配置
- 发布流程、版本管理、数据迁移、错误监控与崩溃上报
- Epic / Sub-issues / Projects 看板、guard Action、PR 与 Issue 关联、搁置项登记

**不纳入：**
- 代码内部结构（见 B1）
- 产品功能是否合理（见 B3）

## 3. 输入

- `docs/audit/AUDIT_BASELINE.md`（评分标准、分级、证据要求、发现格式——必须先通读）
- `docs/audit/facts/<日期>/`（第 0 轮"事实底稿"。若目录不存在或缺少你需要的数据，先在报告中列出缺口，再自行用工具补取，并把原始输出存入该目录）
- 仓库全部源码、`docs/`、Epic / Issue / PR 记录、CI 配置

## 4. 检查清单

### A. 测试与发布
- [ ] 测试金字塔：各层用例数量、运行时长、失败率
- [ ] 关键路径（首次启动 → 设定目标 → 首次专注 → 回访 → 备份/恢复）是否有自动化覆盖？列出缺口
- [ ] e2e flaky 率与超时：既有分类治理是否仍然有效？近 30 次 CI 运行统计
- [ ] 覆盖率：行/分支覆盖率 + "高风险但零覆盖"模块清单
- [ ] 测试质量：有无只断言"不报错"的弱断言、过度 mock、与实现耦合的脆弱用例
- [ ] 回归拦截能力：抽查最近 10 个缺陷修复 PR，是否带回归测试？
- [ ] 发布流程：是否有 checklist、版本号规则、变更日志、签名/公证（Windows / macOS）
- [ ] 回滚与迁移：用户数据 schema 升级、降级、回滚是否有方案并被演练过
- [ ] 可观测性：错误监控、崩溃上报、关键事件日志（在隐私允许范围内）
- [ ] AI 相关回归：模型/提示词变更是否触发评测（与 B6 衔接，只审流程，不审内容）

### B. 项目管理
- [ ] Epic 覆盖度：所有活跃工作是否都挂在 Epic 下？孤儿 PR / Issue 清单
- [ ] 可追溯性：PR ↔ Issue ↔ Epic ↔ 决策文档链路是否完整
- [ ] 搁置项（如 T54 等）：是否有登记、复盘条件、负责人
- [ ] 度量：DORA 四指标估算（部署频率、变更前置时间、变更失败率、恢复时间）与周期时间、WIP
- [ ] 计划与实际：近 8 周计划完成率、范围蔓延情况
- [ ] 文档健康度：新人 / 新 Agent 能否靠文档上手？列出"必须口头传承"的知识
- [ ] 治理成本：任务线体系、guard Action、Brief 流程本身的开销是否合理
- [ ] 风险管理：当前是否存在风险登记册？（本维度 11 的初评）

## 6. 证据要求

除 `AUDIT_BASELINE.md` 第 6 节通用要求外，本 Brief 特别要求：

- 统计类结论必须给出统计口径（时间窗口、样本数、数据来源命令）
- flaky 结论须给出具体用例名与失败日志链接/摘录
- 覆盖缺口须给出具体模块路径

## 7. 通用规则

1. 只读审计：**不得修改产品代码**。唯一允许写入的位置是 `docs/audit/facts/` 与 `docs/audit/findings/<日期>/`。
2. 每条发现按 `AUDIT_BASELINE.md` 第 7 节格式书写，级别按第 5 节定义，证据按第 6 节要求。
3. `事实 / 推断 / 建议` 分开标注；无证据的结论标 `[假设]` 并写验证方法。
4. 不重复审查已有专项治理的部分：只审"该治理机制是否仍在运转、是否被绕过"，并引用其既有文档。
5. 不得因为"看起来合理"而给高分；无法取得证据的检查项，得分按"证据不足 = 最多 2 分"处理，并写明缺什么证据。
6. 发现 P0（含否决项）时，立刻在输出文件顶部以 `🚩` 标出，不要等到最后。
7. 同一问题跨维度出现时，只在最相关的 Brief 中登记，其余用"见 Bn-xx"引用。
8. 对每个负责的维度，给出 0–4 分评分、评分理由，以及"距离通过线还差什么"。
9. 最后附"本次审计的盲区与局限"（哪些结论需要真人验证、哪些需要运行时数据）。

## 8. 完成标准（Definition of Done）

- [ ] 两个维度均有评分与差距说明
- [ ] 关键路径覆盖矩阵、DORA 估算已产出
- [ ] 所有统计类结论标注口径
- [ ] 风险条目已产出
