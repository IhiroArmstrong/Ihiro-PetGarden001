# Task Brief B2 — 测试、发布与项目管理审计

- 所属基准：`AUDIT_BASELINE.md` v1.1
- 负责维度：③ 测试与发布（10%）、④ 项目管理（8%）
- 建议执行方式：独立新会话，一个会话只做本 Brief
- 输出目录：`docs/audit/findings/<日期>/`

## 1. 目标

评估测试体系能否拦住真实回归，发布与回滚是否可靠，项目管理（任务账、PR、搁置登记）是否可追溯、可度量。

## 2. 范围

**纳入：**

- 单测 / 集成 / e2e / 场景测试（含 SCENARIO_TESTS 与 Local AI 场景映射）、CI 配置
- 发布流程、版本管理、数据迁移、错误监控与崩溃上报
- 任务账（`TASKS.md`、`TEST_TRACKER.md`）、guard Action、PR 与 Issue 关联、搁置项登记

**不纳入：**

- 代码内部结构（见 B1）
- 产品功能是否合理（见 B3）

## 3. 输入

- `docs/audit/AUDIT_BASELINE.md`（必须先通读）
- `docs/audit/facts/<日期>/`
- 仓库全部源码、`docs/`、PR 记录、CI 配置

## 4. 检查清单

### A. 测试与发布

- [ ] 测试金字塔：各层数量、时长、失败率（口径写清）
- [ ] 关键路径自动化覆盖矩阵（缺口标未检或待补）
- [ ] e2e flaky 与超时：分类治理是否仍有效？抽样统计（口径写清）
- [ ] 覆盖率与高风险零覆盖模块
- [ ] 回归拦截：近若干缺陷修复 PR 是否带回归测试（抽样）
- [ ] 发布流程与版本规则
- [ ] 回滚与迁移：是否可复述且有过演练或证据
- [ ] 可观测性：崩溃与错误通道（隐私边界内）
- [ ] AI 相关回归流程（与 B6 衔接，只审流程）

### B. 项目管理

- [ ] 任务账覆盖：活跃工作是否可从 TASKS/TEST_TRACKER/PR 链追到？
- [ ] 孤儿 PR/Issue 清单（若有）
- [ ] 搁置项是否有登记与复盘条件
- [ ] **（可选）** DORA 四指标：若尚无仪表，记「未采用」，**不**单独扣分；若估算，写清假设
- [ ] 文档上手性：新人/Agent 能否从权威文档切入（列缺口）
- [ ] 维度 11：风险登记册是否存在？若否，记「未建立」（与基准第 3.4 节一致）

## 5. 输出格式

产出文件：`docs/audit/findings/<日期>/B2-testing-release-pm-findings.md`。

评分须含「检状态」。**DORA 估算表改为可选**；未做时写明未检原因。

## 6. 证据要求

统计类结论须给出时间窗口、样本数、数据来源命令。

## 7. 通用规则

只读审计；格式见 `AUDIT_BASELINE.md`。未检不打分。

## 8. 完成标准（Definition of Done）

- [ ] 两维度有检状态与（已检部分的）过线判断
- [ ] 关键路径覆盖矩阵已填或明确未检项
- [ ] 风险登记册「未建立」已显式写出（若适用）
