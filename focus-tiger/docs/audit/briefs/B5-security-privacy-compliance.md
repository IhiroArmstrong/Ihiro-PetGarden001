# Task Brief B5 — 安全、隐私与合规审计

- 所属基准：`AUDIT_BASELINE.md` v1.0
- 负责维度：⑨ 安全、隐私与合规（10%）；**含一票否决项 V1、V3、V4**
- 建议执行方式：独立新会话，一个会话只做本 Brief
- 输出目录：`docs/audit/findings/<日期>/`

## 1. 目标

评估产品在数据收集、同意、备份与上传、存储与传输安全、依赖与密钥管理方面是否达到面向欧美用户发布的最低要求；识别否决项与合规硬伤。

## 2. 范围

**纳入：**
- 所有用户数据的产生、存储、传输、上传、备份、删除路径
- 研究共修（Practice Study）三层数据方案与同意页三语文案、上传接口
- 数据备份与恢复、邮件订阅、支付/订阅（Stripe 等）、权限与 entitlement
- 依赖与供应链、密钥与配置、构建与发布产物

**不纳入：**
- 模型输出内容质量与危机路由（见 B6，但"数据是否被不当上传"归本 Brief）
- 代码风格类问题（见 B1）

## 3. 输入

- `docs/audit/AUDIT_BASELINE.md`（评分标准、分级、证据要求、发现格式——必须先通读）
- `docs/audit/facts/<日期>/`（第 0 轮"事实底稿"。若目录不存在或缺少你需要的数据，先在报告中列出缺口，再自行用工具补取，并把原始输出存入该目录）
- 仓库全部源码、`docs/`、Epic / Issue / PR 记录、CI 配置

## 4. 检查清单

- [ ] **数据地图**：列出每一类数据（来源 / 用途 / 存储位置 / 是否离开设备 / 保留期 / 删除方式 / 法律依据或同意依据）
- [ ] **V1 检查**：任何数据离开设备之前，是否有明确、可撤回、粒度合适的同意？默认值是否为"不上传"？逐条走查所有网络请求（附请求清单）
- [ ] 同意与撤回：同意页文案是否清晰、是否捆绑、三语是否一致；撤回后上传是否真的停止且已上传数据可删除
- [ ] 数据最小化与匿名化：研究数据是否可重识别；日志中是否含个人内容（含 Confide 对话文本）
- [ ] 用户权利：访问、导出、删除、撤回同意的实现情况（GDPR / CCPA 要点对照，标注"法务确认项"，不得下法律结论）
- [ ] 未成年人：是否有年龄相关处理；面向的情绪类对话对未成年人的风险
- [ ] **V4 检查**：备份/恢复流程、升级迁移、误删场景下用户数据能否找回；是否有端到端演练记录
- [ ] 传输与存储：TLS、本地存储加密、备份加密、密钥管理方式
- [ ] 接口安全：上传接口的认证、限流、输入校验、越权、日志脱敏
- [ ] STRIDE 威胁建模：至少覆盖 本地应用 / 上传接口 / 支付订阅 / AI 调用 四个边界
- [ ] **V3 检查**：依赖漏洞扫描（含传递依赖）、许可证兼容性、锁文件、供应链风险（postinstall 脚本、不再维护的包）
- [ ] 密钥与配置：仓库与历史提交中是否有密钥泄漏（扫描并记录结果）
- [ ] 提示词注入与本地 AI 操作类功能（如语音指令办理备份等）：越权执行、误触发、确认机制
- [ ] 第三方服务清单与数据处理关系（子处理者），隐私政策与实际行为是否一致
- [ ] 支付与订阅：退款/取消路径、欧盟消费者要求（标注为"法务确认项"）

## 6. 证据要求

除 `AUDIT_BASELINE.md` 第 6 节通用要求外，本 Brief 特别要求：

- 每条数据流须给出代码位置（路径:行号）与实际抓取到的请求样例（脱敏）
- 漏洞结论须附扫描工具名称、版本、命令与原始输出
- 合规判断统一写为"对照 XX 要求，存在/不存在缺口"，不得出具法律意见，并列入"法务确认项"
- 密钥扫描结果中不得在报告里复现密钥原文

## 7. 通用规则

1. 只读审计：**不得修改产品代码**。唯一允许写入的位置是 `docs/audit/facts/` 与 `docs/audit/findings/<日期>/`。
2. 每条发现按 `AUDIT_BASELINE.md` 第 7 节格式书写，级别按第 5 节定义，证据按第 6 节要求。
3. `事实 / 推断 / 建议` 分开标注；无证据的结论标 `[假设]` 并写验证方法。
4. 不重复审查已有专项治理的部分：只审"该治理机制是否仍在运转、是否被绕过"，并引用其既有文档。
5. 不得因为"看起来合理"而给高分；无法取得证据的检查项，得分按"证据不足 = 最多 2 分"处理，并写明缺什么证据。
6. 发现 P0（含否决项）时，立刻在输出文件顶部以 `🚩` 标出，不要等到最后。
7. 同一问题跨维度出现时，只在最相关的 Brief 中登记，其余用"见 Bn-xx"引用。
8. 对每个负责的维度，给出 0–4 分评分、评分理由，以及"距离通过线还差什么"。
9. 最后附"本次审计的盲区与局限"（哪些结论需要真人验证、哪些需要运行时数据）。
