# Task Brief B4a — UI/UX 与欧美适配审计

- 所属基准：`AUDIT_BASELINE.md` v1.1
- 负责维度：⑥ UI/UX 与欧美适配（14%）、⑧ 性能与资源（6%，**以第 0 轮事实底稿中的数值为准**，本 Brief 负责解读与差距判断）
- 建议执行方式：独立新会话，一个会话只做本 Brief
- 输出目录：`docs/audit/findings/<日期>/`

## 1. 目标

评估产品对欧美笔记本电脑用户的体验质量：首次价值体验速度、英文文案母语水平、视觉与交互成熟度、平台与键盘行为；结合第 0 轮的性能数字判断资源占用是否可接受。

## 2. 范围

**纳入：**

- 全部界面、文案资源（中/英/日等）、动画与音效、主题与响应式（不含 a11y 合规逐项，见 B4b）
- 键盘操作、焦点可见性、Esc 行为（不含屏幕阅读器深度抽测，见 B4b）
- 深浅色模式、HiDPI、窗口缩放与多显示器
- 平台差异：Windows / macOS 的通知、窗口管理、系统设置跟随
- 空状态、加载态、错误态、离线态
- **六类竞争替代**下的体验对照（见 B3 与 `MVP_PRODUCT_DEFINITION.md`），具名应用仅作类内示例；差异化仍是待验证假设，不得写成既定结论
- 对第 0 轮已采集的冷启动、内存、CPU、包体积、（若已测）动画帧率等数据做解读，并标明是否达到基准中的上限建议

**不纳入：**

- WCAG 逐项、a11y 工具扫描、多语言格式与截断（见 B4b）
- 功能是否应存在（见 B3）
- 隐私条款与同意流程的法律判断（见 B5）

## 3. 输入

- `docs/audit/AUDIT_BASELINE.md`（必须先通读）
- `docs/audit/facts/<日期>/`（**性能与资源数字以该目录原始输出为准**；若缺失，维度 ⑥ / ⑧ 对应检查项标「未检」）
- 仓库全部源码、`docs/`、PR / CI、任务账（TASKS / TEST_TRACKER）

## 4. 检查清单

### A. UI/UX 与欧美适配

- [ ] 首次启动：从打开到首次价值体验的步数与耗时（目标 ≤3 分钟，证据驱动）
- [ ] Nielsen 启发式评估，每条给出具体界面例证
- [ ] 认知走查：3 个关键任务（首次专注 / 中断后恢复 / 查看成长）
- [ ] 英文文案：是否自然、翻译腔、语气是否符合品类期待；列出待母语者重写清单（标「待真人验证」）
- [ ] 文化适配：禅/修行隐喻在欧美语境的可理解度；健康/疗愈类宣称是否克制
- [ ] 视觉一致性：设计 token、叠层 UI 契约遵守情况
- [ ] 深浅色、HiDPI、窗口与多显示器
- [ ] 键盘优先：全局快捷键、Tab 顺序、焦点可见性
- [ ] 与**六类替代**的界面级对照（具名产品仅作类内例子，附来源与日期）

### B. 性能与资源（解读第 0 轮）

- [ ] 核对 `facts/<日期>/` 中：冷启动、首屏可交互、常驻内存/CPU、包体积、（若有）动画帧率
- [ ] 若事实底稿缺少桌面练习壳测量，不得用宣传站 Lighthouse 得分代替；标「未检」并写明需要补什么命令/环境
- [ ] 为适用指标写出「观察值 vs 建议上限」及差距

## 5. 输出格式

产出文件：`docs/audit/findings/<日期>/B4a-uiux-western-findings.md`。

评分表须含「检状态」列（已检 / 部分已检 / 未检）。

## 6. 证据要求

- UI/UX 发现须附截图，并标注：OS、分辨率、缩放、主题、语言
- 性能解读须引用事实底稿中的文件路径（不要求在报告内重复大段原始日志）

## 7. 通用规则

见 `AUDIT_BASELINE.md`。只读审计；不写产品代码。

## 8. 完成标准（Definition of Done）

- [ ] 维度 ⑥ 有完整评分流程或明确的未检说明与覆盖率
- [ ] 维度 ⑧：要么基于事实底稿给出判断，要么整维标「未检」
- [ ] 依赖真人或母语者的结论已标「待真人验证」
