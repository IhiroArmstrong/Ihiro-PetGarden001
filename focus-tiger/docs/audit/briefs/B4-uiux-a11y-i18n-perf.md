# Task Brief B4 — UI/UX、欧美适配、可访问性、国际化与性能审计

- 所属基准：`AUDIT_BASELINE.md` v1.0
- 负责维度：⑥ UI/UX 与欧美适配（14%）、⑦ 可访问性与国际化（6%）、⑧ 性能与资源（6%）
- 建议执行方式：独立新会话，一个会话只做本 Brief
- 输出目录：`docs/audit/findings/<日期>/`

## 1. 目标

评估产品对欧美笔记本电脑用户的体验质量：首次价值体验速度、英文文案母语水平、视觉与交互成熟度、可访问性、多语言质量、性能与资源占用；找出不足并给出优化计划。

## 2. 范围

**纳入：**
- 全部界面、文案资源（中/英/日等）、动画与音效、主题与响应式
- 键盘操作、焦点管理、屏幕阅读器语义
- 冷启动、常驻资源、动画帧率、耗电

**不纳入：**
- 功能是否应存在（见 B3）
- 隐私条款与同意流程的法律判断（见 B5）

## 3. 输入

- `docs/audit/AUDIT_BASELINE.md`（评分标准、分级、证据要求、发现格式——必须先通读）
- `docs/audit/facts/<日期>/`（第 0 轮"事实底稿"。若目录不存在或缺少你需要的数据，先在报告中列出缺口，再自行用工具补取，并把原始输出存入该目录）
- 仓库全部源码、`docs/`、Epic / Issue / PR 记录、CI 配置

## 4. 检查清单

### A. UI/UX 与欧美适配
- [ ] 首次启动体验：从打开到完成首次价值体验的步数与耗时（目标 ≤3 分钟）
- [ ] Nielsen 10 条启发式逐条评估，每条给出 ≥1 个具体界面例证
- [ ] 认知走查：3 个关键任务（首次专注 / 中断后恢复 / 查看成长）
- [ ] 英文文案：逐屏检查是否自然、是否有翻译腔、语气是否符合欧美用户对"专注/冥想/陪伴"类产品的期待；标出需要母语者重写的文案清单
- [ ] 文化适配：吉祥物、隐喻、禅/修行类措辞在欧美语境的可理解度与潜在误解；健康/疗愈类宣称是否克制
- [ ] 视觉一致性：设计 token、间距、字体、图标风格、叠层 UI 契约的实际遵守情况
- [ ] 深浅色模式、HiDPI、窗口缩放与多显示器行为
- [ ] 键盘优先：全局快捷键、Tab 顺序、焦点可见性、Esc 行为
- [ ] 平台差异：Windows / macOS 的通知、窗口管理、系统设置跟随
- [ ] 空状态、加载态、错误态、离线态的文案与视觉
- [ ] 与竞品的体验对照（与 B3 竞品清单共用，补充界面级截图对比）

### B. 可访问性与国际化
- [ ] 用 axe / Lighthouse 或等价工具扫描，列出违规项及对应 WCAG 2.2 AA 条款
- [ ] 色彩对比度、字号可缩放、动效减弱（prefers-reduced-motion）、闪烁与自动播放控制
- [ ] 语义与 ARIA：关键控件是否有可访问名称；动态内容是否有 live region
- [ ] 屏幕阅读器抽测（NVDA / VoiceOver）：至少 2 个关键任务
- [ ] i18n：硬编码字符串扫描、占位符与复数处理、文本膨胀导致的截断、多语言混用（含 AI 输出语言一致性）
- [ ] 日期/时间/时区/数字/货币格式；周起始日；夜间跨日逻辑
- [ ] 欧盟无障碍法案（EAA）适用性初判（标注为"法务确认项"，不得下法律结论）

### C. 性能与资源
- [ ] 冷启动时间、首屏可交互时间
- [ ] 常驻内存、CPU 占用（空闲/专注中/动画中），连续运行 8 小时的内存趋势
- [ ] 动画帧率与掉帧场景；低配笔记本（建议基线：4 核 / 8GB / 集成显卡）表现
- [ ] 耗电影响（尽可能给出测量方法与数据，无法测量则标 `[假设]`）
- [ ] 包体积、依赖体积 Top 10、懒加载情况
- [ ] 为每项指标提出"基线值 + 上限值"建议，供写入后续基准

## 6. 证据要求

除 `AUDIT_BASELINE.md` 第 6 节通用要求外，本 Brief 特别要求：

- UI/UX 发现必须附截图，并标注：OS、分辨率、缩放比例、主题、语言
- 性能数据：给出测量工具、命令、环境，至少 3 次取中位数
- a11y：附工具原始报告路径 + 违规元素选择器/文件位置
- 所有"欧美用户会怎么想"类结论一律标 `[假设]`，并写明建议的真人验证方式

## 7. 通用规则

1. 只读审计：**不得修改产品代码**。唯一允许写入的位置是 `docs/audit/facts/` 与 `docs/audit/findings/<日期>/`。
2. 每条发现按 `AUDIT_BASELINE.md` 第 7 节格式书写，级别按第 5 节定义，证据按第 6 节要求。
3. `事实 / 推断 / 建议` 分开标注；无证据的结论标 `[假设]` 并写验证方法。
4. 不重复审查已有专项治理的部分：只审"该治理机制是否仍在运转、是否被绕过"，并引用其既有文档。
5. 不得因为"看起来合理"而给高分；无法取得证据的检查项，得分按"证据不足 = 最多 2 分"处理，并写明缺什么证据。
6. 发现 P0（含否决项）时，立刻在输出文件顶部以 `🚩` 标出，不要等到最后。
7. 同一问题跨维度出现时，只在最相关的 Brief 中登记，其余用"见 Bn-xx"引用。
8. 对每个负责的维度，给出 0–4 分评分、评分理由，以及"距离通过线还差什么"。
9. 最后附"本次审计的盲区与局限"（哪些结论需要真人验证、哪些需要运行时数据）。

## 8. 完成标准（Definition of Done）

- [ ] 三个维度均有评分与差距说明
- [ ] 文案重写清单、启发式评估表、a11y 清单、性能基线表已产出
- [ ] 所有需要真人验证的结论已列入"待验证清单"，附建议的试用任务脚本（3–5 个任务）
- [ ] 已列出无法在本环境测量的指标及所需设备/工具
