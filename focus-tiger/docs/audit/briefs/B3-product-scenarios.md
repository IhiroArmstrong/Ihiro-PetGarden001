# Task Brief B3 — 产品功能与场景审计

- 所属基准：`AUDIT_BASELINE.md` v1.1
- 负责维度：⑤ 产品功能与场景（12%）
- 建议执行方式：独立新会话，一个会话只做本 Brief
- 输出目录：`docs/audit/findings/<日期>/`

## 1. 目标

评估产品功能是否围绕清晰定位、核心场景能否端到端完成、功能之间是否冲突或过度堆叠；并在 **`MVP_PRODUCT_DEFINITION.md` 的六类竞争替代**框架下审视价值叙事。**不得**把差异化写成既定事实。

## 2. 范围

**纳入：**

- 全部用户可见功能与入口（专注、Yin 陪伴、Confide、冷启动、Ground Exercise、成长旅程、语音指令、研究共修、引导冥想等——以代码与场景文档为准）
- 场景文档（`SCENARIO_TESTS.md` 等）与实际行为的一致性
- 商业化相关入口（付费、订阅、备份）

**不纳入：**

- UI 视觉与欧美文案质感（见 B4a）
- 可访问性与多语言格式（见 B4b）
- 代码质量（见 B1）

## 3. 输入

- `docs/audit/AUDIT_BASELINE.md`（必须先通读）
- `docs/audit/facts/<日期>/`
- **`MVP_PRODUCT_DEFINITION.md`**（「竞争替代品」六类为**唯一**必选对标框架）
- `SCENARIO_TESTS.md`、`FEATURE_CONFLICT_REVIEW.md`
- 仓库全部源码、`docs/`、PR 与任务账

## 4. 检查清单

- [ ] 产品定位一句话：从代码与文案反推，并与 `PRODUCT_POSITIONING.md` / MVP 定义对照
- [ ] 功能清单：功能 / 入口 / 首次出现位置 / 与定位关系
- [ ] 核心场景（至少 5 个）端到端走查：新用户首次启动 / 开始专注 / 被打断 / 情绪低落求助 / 回访与成长 / 备份恢复
- [ ] 每个场景：步骤、卡点、异常/空状态、退出路径
- [ ] 功能冲突与重叠（与 FEATURE_CONFLICT_REVIEW 对齐）
- [ ] 功能密度与打扰：主动触发是否可关闭、是否与「专注陪伴」定位相悖
- [ ] 价值闭环与商业化边界
- [ ] **六类竞争替代对标表**（必选）：对每一类至少回答「本产品是否承担这一类任务、承担到什么程度、证据是什么」。**具名 App**（如 Forest 等）仅可作某一类内的**例子**，须附信息来源与访问日期；**不得**用具名清单替代六类框架
- [ ] 欧美笔记本语境：哪些功能依赖特定文化语境——标 `[假设]` 与待真人验证
- [ ] 抽查 ≥10 条 `SCENARIO_TESTS.md` 场景与实现一致性

## 5. 输出格式

产出文件：`docs/audit/findings/<日期>/B3-product-scenarios-findings.md`。

评分含「检状态」。**未检不得给分**。

`## 3.1 补充产出`：功能清单表、5+ 场景走查记录、**六类替代对标表**（非具名竞品表）。

## 6. 证据要求

- 场景走查：可复现步骤与环境
- 对标：每条结论须能指向代码/文案/场景 ID

## 7. 通用规则

只读审计。发现格式见 `AUDIT_BASELINE.md`。

## 8. 完成标准（Definition of Done）

- [ ] 六类替代对标完成（或明确未检子项）
- [ ] 无「差异化已验证」类表述，除非有用户证据
- [ ] 待真人验证项已列表
