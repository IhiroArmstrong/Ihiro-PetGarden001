# AUDIT_BASELINE.md — 项目与产品审计基准

- 版本：v1.0
- 适用范围：Focus Tiger 仓库内全部项目、产品与工程管理
- 用途：每次审计的统一"尺子"。审计者（人或 AI Agent）按本文件打分、出具发现、制定整改计划
- 基准本身需要迭代：每次审计结束时更新文末"修订记录"

---

## 1. 审计原则

1. **证据驱动**：每条发现必须带证据（文件路径 + 行号 / 复现步骤 / 命令输出 / 截图）。无证据的只能标为"假设"。
2. **先工具，再判断**：先取得客观数据（静态分析、依赖扫描、覆盖率、axe/Lighthouse、包体积），再做判断。
3. **三类内容分开写**：`事实`（可验证）/ `推断`（基于事实的判断）/ `建议`（要做什么）。不得混写。
4. **分级而非罗列**：统一使用 P0–P3，并标注修复成本与影响面。
5. **审"治理是否仍有效"，而非从头重审**：已有专项治理的部分（如 e2e 分类治理、叠层 UI 契约、成长度量、Confide 路由评测分层），审查其机制是否仍在运转、是否被绕过。
6. **闭环**：每条 P0/P1 必须对应一个 Epic 或 Issue，不允许只躺在报告里。
7. **承认 AI 审计盲区**：真实用户行为、留存、真实设备体感无法由 AI 取得。UX 与欧美市场适配的结论必须标注"待真人验证"，直到完成真人试用。
8. **交叉复核**：P0/P1 级结论（安全、合规、架构）须由另一模型或另一轮独立会话复核。

## 2. 审计时点

| 时点 | 深度 | 目的 |
|---|---|---|
| 首次基线审计（距目标发布 6–8 周以上） | 完整（全部 11 个维度） | 建立评分卡与风险登记册，留足整改时间 |
| 每个 PR / 日常 | 自动化检查 | lint、依赖扫描、架构适应度函数、e2e 守门 |
| 每个里程碑结束 | 轻量复审 | 只审变化部分 + P0/P1 整改是否落地 |
| 发布前 1–2 周 | 发布门禁审计（1–2 天） | 只查"一票否决项"与上次 P0/P1 是否关闭 |
| 发布后 30 / 90 天 | 数据驱动复审 | 用真实留存、崩溃、反馈补盲区，修订本基准 |
| 事件触发 | 专项审计 | 更换底层模型；改动数据上传/备份逻辑；进入新市场（如正式面向欧盟）；重大安全或舆情事件；大规模重构后 |

完整审计之后，到发布之间应至少预留剩余时间的 30%–40% 用于整改。真人试用安排在整改之后、发布门禁之前。

## 3. 评分维度与通过线

评分等级：**0** 缺失 / **1** 临时性做法 / **2** 有做法但不稳定 / **3** 稳定可复现 / **4** 有度量且持续改进。

| # | 维度 | 权重 | 通过线 | 核心检查项 | 负责 Brief |
|---|---|---|---|---|---|
| 1 | 架构 | 12% | ≥3 | 模块边界清晰；依赖方向无环；核心流程有 C4 图；关键决策有 ADR；架构约束有自动化检查（适应度函数） | B1 |
| 2 | 代码质量 | 12% | ≥3 | lint/类型检查零错误；高复杂度函数有清单；重复/死代码低于阈值；PR 平均规模可评审 | B1 |
| 3 | 测试与发布 | 10% | ≥3 | 关键路径有自动化覆盖；flaky 率低于约定；有回滚与数据迁移方案；崩溃/错误可观测 | B2 |
| 4 | 项目管理 | 8% | ≥3 | Epic 覆盖全部活跃工作；PR 与 Issue 可追溯；搁置项有登记与复盘条件；周期时间可度量 | B2 |
| 5 | 产品功能与场景 | 12% | ≥3 | 核心场景端到端可完成；功能间无冲突；空状态/异常状态完整；功能数量与产品定位一致（不过度堆叠） | B3 |
| 6 | UI/UX 与欧美适配 | 14% | ≥3 | 首次启动 3 分钟内完成首次价值体验；英文文案母语级；深浅色模式、键盘操作、HiDPI 正常；与同类竞品对照无明显落差 | B4 |
| 7 | 可访问性与国际化 | 6% | ≥3 | WCAG 2.2 AA 关键项通过；屏幕阅读器可用；多语言无截断/混用；日期时区正确 | B4 |
| 8 | 性能与资源 | 6% | ≥3 | 冷启动、常驻内存/CPU、耗电、动画帧率有基线值与上限 | B4 |
| 9 | 安全、隐私与合规 | 10% | ≥3 且无否决项 | 数据最小化；同意与撤回；备份与上传的加密及删除权；依赖漏洞扫描；密钥管理；威胁建模 | B5 |
| 10 | AI 质量与安全 | 8% | ≥3 且无否决项 | 评测集（开发/盲测/holdout）分层；危机与越界话题路由通过红队用例；模型版本变更有回归；健康宣称克制 | B6 |
| 11 | 风险管理 | 2% | ≥3 | 风险登记册含概率/影响/责任人/触发信号，每季度更新 | 汇总轮 |

**加权总分** = Σ(维度得分 × 权重) / 4 × 100。总分仅作趋势参考；**判定以"各维度是否过线 + 是否触发否决项"为准**。

## 4. 一票否决项

任一项不通过，即判定"不可发布 / 不可推广"，无论总分多高：

- **V1** 未经用户同意收集或上传用户数据
- **V2** 危机类话题（自伤、自杀、对他人的伤害意图等）无可靠安全路由
- **V3** 已知高危漏洞未处理
- **V4** 数据丢失类缺陷无恢复路径

## 5. 发现分级

| 级别 | 定义 | 处理要求 |
|---|---|---|
| **P0** | 触发否决项，或造成数据丢失、安全/合规事故、核心流程不可用 | 阻断发布；立即建 Issue，进入当前迭代 |
| **P1** | 严重影响核心体验、可维护性或可信度，但有绕行办法 | 发布前必须关闭或有书面豁免 |
| **P2** | 明显不足，不影响核心流程 | 排入 90 天整改计划 |
| **P3** | 可选优化 | 进入待办池 |

每条发现同时标注：**修复成本** S（≤1 天）/ M（≤1 周）/ L（>1 周）；**影响面**（全部用户 / 部分场景 / 内部）。

## 6. 证据要求（所有审计通用）

| 发现类型 | 必须附带的证据 |
|---|---|
| 代码 / 架构 | 文件路径 + 行号；必要时附命令输出（如依赖图、复杂度报告） |
| 行为缺陷 | 复现步骤 + 期望结果 + 实际结果 |
| UI/UX | 截图（标注环境：OS、分辨率、主题、语言） |
| 性能 | 测量命令/工具、测量环境、原始数值（至少 3 次取中位数） |
| 合规/安全 | 数据流描述 + 涉及的文件/接口 + 对应条款或标准编号 |
| AI 质量 | 输入样例、模型输出、所用模型与版本、评测集名称 |
| 假设 | 明确标注 `[假设]`，并写出验证方法 |

## 7. 发现条目标准格式

```markdown

- 级别：P0 | P1 | P2 | P3
- 类型：事实 | 推断 | 建议
- 修复成本：S | M | L
- 影响面：全部用户 | 部分场景 | 内部
- 描述：
- 证据：
  - （路径:行号 / 命令输出 / 截图路径 / 复现步骤）
- 影响：
- 建议整改：
- 建议负责人：
- 关联 Epic / Issue：（无则写"待建"）
- 复核状态：未复核 | 已复核（复核人/模型、日期）
```

## 8. 每次审计的固定产出

1. 评分卡（第 3 节表格 + 与上次对比）
2. P0–P3 发现清单（第 7 节格式）
3. 90 天整改计划（按 P 级与依赖排序，含里程碑）
4. 风险登记册更新（5×5 概率-影响矩阵 + 责任人 + 触发信号）
5. 基准修订记录

## 9. 执行流程

- **第 0 轮 · 工具取证（约半天）**：产出"事实底稿"，存放于 `docs/audit/facts/<日期>/`。包括：静态分析、类型检查、依赖与许可证扫描、测试覆盖率与 flaky 统计、axe/Lighthouse、打包体积、启动与内存基线、Epic/PR 统计。
- **第 1 轮 · 分维度审计**：按 `docs/audit/briefs/` 下 6 份 Task Brief 各开一个独立会话。输入均为"事实底稿 + 本基准"。输出到 `docs/audit/findings/<日期>/`。
- **第 2 轮 · 汇总与复核**：另一模型独立复核全部 P0/P1；汇总评分卡、风险登记册、90 天计划；更新本基准修订记录。
- **第 3 步 · 真人验证**：整改后安排 5–8 人试用（至少 3 位欧美笔记本用户），补充 B3/B4 的"待真人验证"结论。

## 10. 方法参考

| 领域 | 方法 / 标准 |
|---|---|
| 整体质量模型 | ISO/IEC 25010 |
| 架构 | C4 模型；ATAM；架构适应度函数 |
| 代码 | SQALE / 技术债分级；圈复杂度；耦合度；依赖方向检查 |
| 项目管理 | DORA 四指标；WIP；周期时间 |
| 安全 | STRIDE；OWASP ASVS |
| 隐私 | GDPR / CCPA 要点；数据最小化；DPIA 思路 |
| UX | Nielsen 10 条启发式；认知走查；JTBD；关键路径任务测试 |
| 可访问性 | WCAG 2.2 AA；欧盟无障碍法案（EAA） |
| AI | OWASP LLM Top 10；NIST AI RMF；红队用例集；回归评测集 |
| 风险 | 5×5 概率-影响矩阵；FMEA |
