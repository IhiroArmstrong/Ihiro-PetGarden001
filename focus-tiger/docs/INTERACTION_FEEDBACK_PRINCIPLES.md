## 核心原则

**「功能测试通过」和「用户点击后有可感知反应」是两件不同的事。** 评审与自动化现在必须分开测这两层，禁止只测前者。

任何可点击元素被点击后，必须在约 **100ms** 内让用户感知到「点击已被系统接收」——无论最终效果是立即生效、延迟生效，还是本次不生效。

「点击的即时反馈」和「操作的最终结果」必须分开设计、分开测试：

| 层级 | 是什么 | 产品里已有的好例子 |
|---|---|---|
| **接收反馈** | 点击那一刻，0–100ms 内的视觉/状态变化，证明「系统收到了」 | 按压态、`nod-bow`、面板展开动效 |
| **结果反馈** | 操作真正生效后的确认 | `#reminder-preference-saved` 短暂确认、Save image 下载完成 |
| **延迟 / 无反应说明** | 这次点击**按设计就是不生效**（冷却中、门槛未到）时，必须让用户理解「为什么」 | 缺口：未进白名单的沉默一律当 bug |

---

## 规则

### 1. 禁止「哑点击」（dead click）

任何按钮 / 图标被点击，哪怕最终什么都不做，也必须有最低限度的接收反馈（按压高亮、轻微缩放、光效闪一下）。不允许「点了跟没点一样」。

与回归锁「可点却逻辑静默 `return`」互补：那边管**门闩未就绪应禁用/隐藏**；本条管**控件仍可点时不得毫无接收反馈**。

### 2. 「暂不生效」和「永久不生效」都要有说明

- **暂不生效**（冷却中，如 Tiger Anchor 180s）：应能感知「现在还不行」，而不是彻底沉默。极轻暗示即可（触点淡出 / 变灰）。
- **门槛未到**（如 Re-focus 离开 &lt;20s 不记账）：若产品决策就是完全不反应，必须写入 [`SILENT_BEHAVIORS.md`](./SILENT_BEHAVIORS.md) 并标成**已知的静默**，禁止留白让人猜是不是漏了。

### 3. 沉默白名单

所有「设计上就该没反应」的场景只登记在 `SILENT_BEHAVIORS.md`。  
**不在白名单里的沉默，测试时一律判定为 bug**，不必每次猜「这是不是故意的」。

### 4. 场景验收必填：点击后 0–1 秒

`SCENARIO_TESTS.md` 每个**含可点击步骤**的新场景 / 改写场景，必须写清：

> **点击后 0–1 秒内，用户应该看到什么？**

若该步按设计不生效，须点名白名单 id（如 `SB-01`），禁止只写「无反应」。

存量场景**禁止**「随改写再补」。补句优先级表在 `SCENARIO_TESTS.md` 文首，跟踪行在 `TEST_TRACKER`。

### 5. 下一步能做什么要显性

状态切换类操作（保存偏好、完成微仪式等）：反馈除了确认「完成了」，还要给出「你现在可以做 A 或 B」的线索——按钮高亮、面板收起露出下一步入口即可，不必额外弹窗说教。

### 6. 无障碍

纯视觉反馈（轻微光效）屏幕阅读器感知不到。凡**结果反馈**层，须同时挂 `aria-live` 文字播报，不能只做视觉动效。接收反馈（按压态）不强制 live 区域。

## Agent / PR 落地（强制）

任何新增或修改的可点击交互，必须在 **PR 描述**里回答（现为 **三问**）：

1. **点击后 0–1 秒内用户会看到什么？**
2. **如果本次操作按设计不生效，属于 `SILENT_BEHAVIORS.md` 里哪一条？不在白名单里的沉默视为 bug。**
3. **冲突扫描结论**（对照 `SCENARIO_TESTS.md`）——全文见 [`FEATURE_CONFLICT_REVIEW.md`](./FEATURE_CONFLICT_REVIEW.md)（`RULES_INDEX` → `feature-conflict-review`）；本页不展开扫描细则。Q3 对所有非机械改动生效，不限于可点击交互。

Cursor 摘要见 `.cursor/rules/focus-tiger-interaction-feedback.mdc`；PR 模板有对应栏。勿在其它文档复述本页六条全文。
