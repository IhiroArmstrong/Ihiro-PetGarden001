## 0. 大白话

Thought Drop / 觉察一句已经能让人写下心里闪过的一句、被固定句接住。那是**第一层**：不是聊天、不存原文、不当日记。

**Inner Mirror（内在镜子）是同一入口上默认关闭的第二层。** 只有用户明确点过「留下」，本机才保存那一句。攒过一段时间之后，用户**自己点开**，镜子用本地记录帮他看见自己前后说了什么——不贴标签、不替他解释自己是谁。

用户说「我不完全这样认为」时，镜子改口并记住这次纠正，以后不得再搬出被否定的判断。关授权或点「忘掉」后，原文、替换句和由此派生的摘要一起真删，镜子当场空白。

**2026-11-26 晚间改口（取代同日「整包顺延、禁止暗发」）：** 12 月 8 日的安装包按里程碑发，不因周回看没做完而整包推迟。首包只保证「留下 / 忘掉 / 纠正」开始攒数据。周回看、攒完问一句、用户自己标记的改变时刻走更新通道，12/8 之后上。月回看、打卡、对话授权不卡这一天。这不是把回看偷偷关掉还假装已经上线。

## 1. 一名 · 四看 · 一层入口

对外统一名：**Inner Mirror / 内在镜子**。禁止再拆成四个产品或四条任务线。

四种回看是**同一面镜子的看法**，不是四个 App：

| 对外名 | 人话 | 本锁时点 |
|---|---|---|
| **Weekly Inner Reflection** | 这一周留下的话里，重复出现了什么 | **更新通道，12/8 之后**。不拖安装包 |
| **「攒完问一句」** | 周回看里可点的一句开放问 | 与周回看同一更新。第一版**固定模板，零生成** |
| **Monthly Growth Reflection** | 近一个月 vs 再前一个月 | **不卡 12/8**。首日没有满月数据 |
| **Personal Pattern Journal** | 纠正过的主题清单 | 数据面进首包；不做新日记本 UI |
| **Moments of Change** | 用户自己点「这是一次改变」 | 与周回看同一更新；**禁止**自动颁发 |

**不挂在成长旅程圆点上**（圆点只读坐下分钟，见 [`GROWTH_JOURNEY.md`](./GROWTH_JOURNEY.md)）。

首周多数人只会看到「还不够」：窗内留下要满 3 条，且同一个规则键也要满 3 条。这是设计的代价，不是缺陷。上线说明须照实写。

## 4. 三条硬约束（实现 Brief 必须可检验）

### 4.1 纠正权持久且可检查（灵魂）

用户改写或作废的观察，**之后不得再出现**。须有结构化记录（主题 id、状态：active / corrected / void、用户替换句），用确定性闸拦截，**不能只靠提示词**。界面须能看见「这条已按你的意思改过」。

用户替换句也是原文：写入前走危机检测；命中则不存这句，主题作废。忘掉时与留下的原文一并删。**不得把替换句或留下的原文直接喂给模型。** 模型与固定模板只接收规则键和次数。

### 4.2 数据不足要诚实；主题用封闭词表

不够条数 / 不够重复 → 固定诚实句「还不够」，**禁止编造**。主题只许 Brief 里写死的 **8** 个规则键（中英词表）。运行时不得加第 9 个。不让模型自由归纳主题。

「攒完问一句」第一版是固定模板，**零生成**。生成版留给更后的更新。

允许的形状：用代码把次数和规则键填进固定句。  
禁止：「你变得更有耐心 / 你在克服自卑 / 回避型人格好转。」（V5、C-01）

### 4.3 「忘掉」是真删，含派生物

关授权或忘掉 → 一并清空：留下的原文、替换句、应用仍掌管的备份快照、缓存、写进阿寅记忆摘要的派生句、诊断导出、应用自己的日志残留。每处一条测试，删不干净就红。

用户已经复制到应用够不着的文件，不得写成全世界都删干净了。

## 6. 里程碑与日期算法（不是开工令）

取代同日早些时候「三项失败则 12/8 整包顺延」。

| 步 | 内容 | 与 12/8 安装包 |
|---|---|---|
| 0 | 本文件 + Brief 修订 | 本治理 PR。**#1896 先不合** |
| 1 | 留下 / 忘掉 / 纠正数据面；真删含派生物 | **12/8 里程碑**。红了不拖整包，改走更新 |
| 2 | 周回看 + 固定模板问句 + 用户标记的改变时刻 + 三项测试 | **更新通道，12/8 后**。不拖安装包 |
| 3 | 月回看 | **不卡** |
| 4 | 勾 2 / 勾 3 / 读 T106 | **不读** |

**日期算法（写死）：**

- 目标点头日 **2026-11-27**。点头晚了 D 天，下面的工作检查点整段 +D 天。**12/8 安装包日期不加 D。**
- 修复周期 = **7** 天。每个里程碑**最多顺延 1 次**。新日期 = 该检查点原日期 + 7 天。第二次仍红：该里程碑改走 12/8 之后的更新，不得再顺延。
- **12/1**（若晚点头则 +D）：步骤 1 的测试是否已绿。没绿只预警，不改 12/8。
- **12/5** 冻结：步骤 1 仍红 → 用掉那一次 +7（新日期 12/12，或冻结日 +7）。数据面错过安装包，改走更新。安装包日期不动。
- **12/4**（+D）：周回看三项。没全过 → 周回看维持更新通道，不宣布安装包顺延。若要再修，最多一次 +7，仍不拖 12/8。
